# D005 · 不做模型微调

- **状态**：已采纳
- **日期**：2026-09-16
- **决策者**：HJ

---

## 背景

「让 AI 像某个人说话」，最直觉的技术路线是**微调（fine-tuning）**：拿聊天记录/剧情文本喂进去，训练一个专属模型。

HJ 在问诊中确认了这一点（Q13 第 7 条）。

---

## 分析

微调需要的投入：

| 项 | 要求 | HJ 的现状 |
|---|---|---|
| 数据量 | 7B 模型至少 16GB 显存；14B+ 才有说服力 | ❌ 本地跑不了 |
| 数据量（材料侧） | 微调一个说话风格，通常需要**上万条**对话 | ⚠️ 亲人聊天记录凑不到；剧情台词也未必够 |
| 环境 | Python + CUDA + 训练框架 全家桶 | ❌ 环境折腾是烂尾高发区 |
| 时间 | 数据清洗 + 多轮训练 + 调参，以天/周计 | ❌ 反馈周期太长 |
| 迭代 | 每次想改人设都要重新训练 | ❌ 与「人格会演化」直接冲突 |
| 可解释性 | 微调后的模型是个黑盒 | ❌ 与可视化目标冲突 |

**最致命的一条**：微调产物是**静态的**。而 HJ 的核心需求是「人格在对话中不断成长改变」。每次演化都重新训练一遍，工程上不成立。

---

## 关键证据

社区实践已经给出了答案：**角色扮演场景不需要微调。**

- SillyTavern（31k★）：纯 Prompt + World Info，社区公认效果足够
- 各类角色扮演产品：主流做法都是 System Prompt + 世界书 + 记忆注入
- 微调真正的价值在**领域知识**和**特殊输出格式**，不在「说话风格」

---

## 选项

| 选项 | 描述 | 后果 |
|---|---|---|
| A · 微调专属模型 | 训练一个「像他」的模型 | 硬件不够、周期长、静态黑盒、与演化需求冲突 |
| B · Prompt 工程 + 人格档案注入 | 用人格剖面构造 System Prompt，每次请求动态拼装 | 立即可用、可解释、可热改、天然支持演化 |
| C · 混合（微调打底 + Prompt 微调） | 先微调再 Prompt | 徒增复杂度，收益不明确 |

---

## 决定

**采纳 B，明确不做微调。** 技术路线：

```
人格档案（冻结层 + 演化层）
        ↓ 拼装
System Prompt = [角色设定] + [说话风格] + [关系上下文] + [命中的记忆]
        ↓
      通用 LLM（云端 API / 本地 Ollama）
```

**冻结人设靠 Prompt 的稳定性保证，人格演化靠演化层数据的更新实现** —— 不需要动模型权重。

---

## 后果

**正面**
- 零训练成本，改人设即时生效
- 完全符合 HJ 的硬件条件
- 人格画像是**显式数据**，可以直接可视化、可以手动编辑 —— 这正是 D001 定下的差异化
- 不引入新知识领域（符合「一个项目只学一样新东西」）

**负面 / 代价**
- 效果上限受底座模型能力限制
- Prompt 变长 → token 成本上升（需要控制注入量）
- 效果调优全靠 Prompt 工程，容易掉进调优黑洞

**风险缓解**
- Phase 0 就是为了验证「Prompt 路线能做到多像」，有硬阈值防止无限调优
- 注入内容设上限，控制成本

---

## 值得记住的判断

> **「像一个人」是行为层面的问题，不是权重层面的问题。**
> 与其训练一个模型变得像他，不如把「他是谁」写成结构化的数据，让通用模型去演。
> 前者是黑盒且不可控，后者是数据且完全透明 —— 而透明正是这个项目存在的原因。
