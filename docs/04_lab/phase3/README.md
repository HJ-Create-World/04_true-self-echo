## 一、完成标准① · 「下一轮被用上」

**验证脚本**：`exp/p3_verify_s2`（P3-2 时执行，9 项全过）

**做法**：第 1 轮说「我妹妹叫小雨，她下个月要过生日了」→
第 2 轮换成一句**不含任何触发词**的话（「你在想什么呢？」）→
抓第 2 轮真正发出的 system prompt，看里面有没有「小雨」。

**结果：有。**

> 这一轮换成不含触发词的话是**故意的** —— 如果第 2 轮还在说妹妹，
> 就算记忆没被注入也可能因为话题本身相关而「碰巧」答对。
> 换成完全无关的话，才能证明记忆是**作为状态**被注入的，不是碰巧。

### ⭐ 这一步逼出了一个设计变更：注入必须两级，不能只靠关键词

D004 定的是「关键词触发」。但实测暴露了它的结构性漏洞：

> 第 1 轮说「我妹妹叫小雨」→ 卡片触发词 `妹妹` / `小雨`
> 第 2 轮说「她最近怎么样」→ **一个触发词都没命中** → 记忆没被注入

而完成标准①恰恰是「**下一轮**被用上」—— 也就是说，
**纯触发式注入在它最该起作用的那一轮最容易失败**。

**解法**：改成两级注入 ——
**常驻区**（重要度最高的 + 最近新增的，无条件注入，保证「刚说的」在）
+ **触发区**（关键词命中，补上「很久以前说过、现在又被提到」）。
代价是常驻区占固定上下文（5 条卡片约 100 字），可忽略。

## 二、完成标准② · 「面板能看到至少 2 次有效变化」

**验证脚本**：`exp/p3_verify_s3`（快照）+ `exp/p3_verify_s4`（图表），合计 20 项全过

**「有效变化」的定义**：不是「聊了一句」，而是**演化层真的变了**。
所以快照只在变化时生成 —— 无变化的一轮是重复点，画在曲线上是噪声，
而且「回滚到它」没有意义。

实测：3 轮对话（2 轮有新事实 + 1 轮纯寒暄）→ **恰好 2 个快照**。

**面板上能看到的变化**（三处，任一处都满足「2 次」）：

| 位置 | 形式 |
|---|---|
| **演化时间线** | 每个快照一行：「新增 1 条记忆」×2，带时间戳 |
| **变化曲线** | 两条折线（记忆条数 / 关系亲密度），3 个数据点 |
| **记忆面板** | 卡片从 1 张变 2 张，按类型分组可见 |

## 三、完成标准③ · 「能回滚到任意历史快照」

**验证脚本**：`exp/p3_verify_s3`（11 项全过）

**做法**：两轮各说一件事实（面包 / 馒头）→ 2 个快照 →
在「档案」页回滚到**最早**的那个 → 验证四件事：

| # | 断言 | 结果 |
|---|---|---|
| 1 | 回滚后记忆集合**精确等于**目标状态（有面包、无馒头） | ✅ |
| 2 | **回滚本身留了一条快照**（2 → 3） | ✅ |
| 3 | frozenHash 仍恒定 | ✅ |
| 4 | **跨 store 同步**：回滚后下一轮的 system 里没有「馒头」 | ✅ |

### ⭐ 为什么第 2 条（回滚也留快照）是刻意设计

如果回滚只是「把状态写回去」，那么回滚之后**想再回到回滚前就做不到了** ——
那等于把历史删了，曲线也会失去「这里发生过回滚」的信息。
所以回滚实现为「读旧快照 → 写回 → **追加一条标记这次回滚**」。

### ⭐ 为什么第 4 条（跨 store 同步）是验收里最重要的一条

回滚发生在 evolution store，但 **chat store 的内存副本还持有回滚前的记忆** ——
不修的话，下一轮的 system prompt 会把被回滚掉的记忆又注入回去。
**而功能看起来完全正常**：按钮有响应、数据库也对、UI 也更新了。
只有发消息才能发现。这是最隐蔽的一类 bug。
（实现上靠 `PersonaView` 在回滚后同步 `chat.persona`。）

## 四、硬约束 · 冻结层不被改写

**SPEC §四：冻结层「AI 不可修改」。** 一个靠聊天就漂移的人格不是「演化」，是「人设崩塌」。

三层落实：

| 层 | 机制 |
|---|---|
| **代码层** | `evolving.ts` 里的任何函数都不接收、不返回 `FrozenLayer` —— 类型上就不可能 |
| **存储层** | `saveEvolving()` 刻意**只写 evolving 一个字段**，避免对话流程顺手把整份档案写回 |
| **观察层** | 每个快照存 `frozenHash`；面板上出现多个指纹 = 有人在编辑器里改了档案（合法，但要标出来），且回滚只还原记忆、不还原人设修改 |

**实测**：全程 1 个指纹 ✅。

## 六、已知局限与下一步

| # | 局限 | 说明 | 建议 |
|---|---|---|---|
| 1 | **关键词触发的弱点仍在** | 「那次我们去的那家店」→「那次」匹配不到。常驻区缓解了「下一轮」场景，但没解决语义检索 | D004 已预留：记忆层是独立的，将来可整体换向量方案而不动其他部分 |
| 2 | **记忆去重只按内容字面** | 「用户的妹妹叫小雨」和「小雨是用户的妹妹」会被当成两条 | 需要 LLM 级语义去重，或按实体归一（Phase 4 数据管理时考虑） |
| 3 | **亲密度是空转的** | `intimacy` 字段存在但**没有任何逻辑推进它**，曲线上永远是一条平线 | Phase 4 或单独一片：定义「什么行为加亲密度」的规则，或由 LLM 每轮评估 |
| 4 | **快照上限 200** | 超过会丢最旧的 —— 与「任意回滚」有张力 | 私人应用 200 轮已极长；真不够时再谈归档策略 |
| 5 | **独白不落库** | 刷新即消失 | 这是设计不是缺陷；若要「回看她说过什么心事」再议 |
| 6 | **记忆卡片不能手动编辑触发词** | D004 的缓解措施之一，尚未实现 | Phase 4 数据管理一起做 |
