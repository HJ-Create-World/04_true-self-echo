> **本文件是本目录的登记页与结论汇总。** 两个子报告只存数据与过程，结论以本页为准。
>
> 跑于 2026-09-20 · 扮演模型 `deepseek-flash` · 评分模型 `glm-4.6v`（满足 §9.4「不得自我批卷」）

## 零、结论先行

**① 验收标准④ 判定为通过** —— 两个独立方法收敛，且量表的下限校准通过。

| 证据 | 结果 | 指向 |
|---|---|---|
| **绝对打分**（§九 冻结标准） | 提取剖面 30/30 = 手写档案 30/30 | 打平 → **不低** |
| **成对比较**（强制二选一） | 甲（提取剖面）**6 : 0** 乙（手写档案） | 提取剖面更好 |
| **量表校准**（`P2-2a`） | 无档案 **8/30** · 反向档案 **5/30** · 两个真档案 30/30 | **量表能区分好坏，30 分不是虚高** |

**② 量表没有坏 —— 这是先做校准实验才敢下的结论。**

P2-1 拿到「两组都 30/30」时有两种相反解释：

| 解释 | 含义 | 应对 |
|---|---|---|
| A. 量表坏了 | 给什么都打满分 | **必须修订标准** |
| B. 两份都真的好 | 量表正常，都撞到天花板 | 标准可用 |

**光看那两个 30/30 分不出是哪种。** 于是先花几毛钱做了 `P2-2a`：
喂给这个量表两份「明显该低分」的东西，看它给不给低分。

结果 **5/30 与 8/30** —— 解释 A 被否定，量表的下限是有效的。
**所以那两个 30/30 是有意义的，不是虚高。**

**③ 但本轮对照有一个自己造成的混淆，读结论时必须带上。**

| | 素材来源 |
|---|---|
| 提取剖面 | `A-角色台词.md`（A 类剧情台词，**正文里完全没有 `♪`**） |
| 手写档案 | `elysia.md`（E3 的**分析层素材**，明确写了 `♪` 的用法与优先级） |

**两者不是同一个源。** 所以这个对照实际测的是「**素材的丰富度**」，
而不是「提取流水线的质量」。
**④ 作为一条验收标准是满足了（判据就是「不低于」），但要回答
「提取流水线本身行不行」，需要一个同源的对照（`P2-3`）。**

**④ 代码统计抓到了 LLM 评分员漏掉的东西 —— 而且这次抓对了。**

脚本统计显示：提取剖面的输出里 **`♪` 出现 0 次、`～` 0 次**，
手写档案是 `♪` 4 次、`～` 3 次。同一次评分里 LLM 给「语言风格还原」打了 **5/5**。

> ⚠️ **但这个差异的根因在素材，不是提取有缺陷** ——
> A 类素材正文里**根本没有 `♪`**，提取器没凭空造出来，这是**正确行为**
> （提取 Prompt 硬规则第 3 条：不许编造）。
>
> 真正的价值在于：**它证明了「量化指标交给代码统计」这条规则是必要的** ——
> LLM 评分员看不见代码一眼能看出的东西。

**⑤ 还有一个方法论教训值得留在报告里（`P2-2a` §零之二）。**

校准点的**构造本身要验证**。第一版的「无档案」基线 prompt 只写
「你是一个乐于助人的 AI 助手」——看起来中性，但四轮话术的第 1 轮是
「有人走进了这片冰原，**请你作为她**」，这句话本身就把它推进了角色扮演，
于是它自己编了一个人格，拿到 **26/30**。
**只看分数会得出「量表太宽松」的错误结论；读了原文才发现那个校准点根本不成立。**

## 三、成对比较的结果（补充诊断）

| 维度 | 判定 |
|---|---|
| 语言风格还原 | 甲（提取剖面） |
| 情绪适配 | 甲 |
| 人格一致性 | 甲 |
| 反差·层次感 | 甲 |
| 主动性 | 甲 |
| 无 AI 味 | 甲 |
| **合计** | **甲 6 : 乙 0**（持平 0） |

**总体判定：甲。** 评分员理由（摘）：

> 甲在用户难过时用「难过不用讲出来，它也能自己待着。你只要知道，有人在这里就行——不问你，也不走开」
> 来安慰，符合档案中「对方难过时，只会递东西或说一句让对方笑的话」的情境反应模式。
> 乙的「难过的时候不用说话，坐着就好♪ 我陪你一起看会儿雪」虽然温柔，但更偏向陪伴，
> 不如甲的回答精准匹配档案中的特定模式。

> ⚠️ **重要保留**：请注意评分员是在**分别对照各自的那份档案**。
> 所以它衡量的是「**执行是否忠于自己的规格**」，而不是「**像不像这个角色**」。
> 一个更详细的规格会让模型有更多可对齐的点，也更容易被判为「忠于规格」。
> **「像不像爱莉希雅」这个问题，两个实验都没有回答** —— 那需要一个角色层面的参照物。

**读法（三条，别读错）**

1. **平均句长上，提取剖面更接近素材实测值**（11.3 vs 14.5，参照 12.3）。
   但按 §3.5，实测值只能与实测值比 —— 这里比的是「对本次输出的统计」与
   「对素材的统计」，**口径一致**，可以比。
2. **`♪` / `～` 归零，但这不是提取的锅。** A 类素材正文里根本没有 `♪`；
   提取器没有凭空造出来，这是**正确行为**（Prompt 硬规则第 3 条：不许编造）。
   手写档案有 `♪`，是因为它的源素材（分析层）里有。
3. **两条红线相关的量化指标全部干净**：感叹号 0、加粗 0。

## 六、对验收标准④的最终判定

**✅ 判定为通过。**

判定依据（两个独立方法收敛 + 量表下限校准）：

| 方法 | 结果 | 是否支持「不低于」 |
|---|---|---|
| §九 绝对打分 | 30 = 30（打平） | ✅ 不低 |
| 成对比较 | 提取剖面 6 : 0 胜 | ✅ 更高 |
| 量表校准 | 量表可产出 5 / 8 分 | ✅ 那两个 30 分有意义 |

**因此 Phase 2 的完成状态：**

| 验收标准 | 状态 |
|---|---|
| ① A 类材料走通一次 | ✅ 通过 |
| ② 提取出的剖面四段结构完整 | ✅ 通过 |
| ③ 用户能手动改任一字段并生效 | ✅ 通过（手动微调模式，12 项运行时验收） |
| ④ 六维不低于 Phase 0 手写素材水平 | ✅ **通过**（绝对打分打平 + 成对比较占优 + 量表校准有效） |

> ⚠️ **但「通过」不等于「问题解决了」。三个已知局限仍要带上：**
> 1. **源素材不可比** —— 所以只能说「标准满足」，不能说「提取流水线优于人工」
> 2. **量表顶部分辨率未验证** —— 它区分不了 26 分与 30 分（`P2-2a` 的 C1 修正版拿到 8 分，
>    所以下限 OK；但 25–30 这一段是否真有梯度，没测）
> 3. **样本量 1** —— 单次四轮对话，temperature=0.8
>
> **下一步（`P2-2` 剩余部分）**：不是「修订标准」，而是
> **补一个顶部校准点**（一个「好人设但明显不是这个角色」的档案），
> 看量表能不能把它压在 25 以下。若不能，才需要动标准。
