## 零、结论先行

**① 验收标准④ 无法用冻结标准判定 —— 因为该标准出现了天花板效应。**

两组档案（提取剖面 / Phase 0 手写档案）用 `评分标准.md` §九 的六维绝对打分，
**都是 30/30、六维全满、零区分度**。评分员给的理由具体、也引了原文，不是敷衍 ——
但它在这个区间里**分不出高下**，所以回答不了「提取剖面有没有达到手写档案的水平」。

> 这不是本次实现的问题，是**标准自身的问题**。
> `评分标准.md` §六 问题 10 早就写了：「本文档自身未经过实际打分验证」。
> 本轮**正是那条待验证项的实测结果**：第一次真实打分就暴露了天花板。

**② 补充证据（成对比较）显示：提取剖面在六个维度上全面不劣于手写档案。**

强制二选一的成对比较结果：**甲（提取剖面）6 : 乙（手写档案）0**（持平 0）。
两次独立运行都是 6:0。

**③ 但代码统计推翻了「语言风格还原」这一维的判定 —— 而且暴露了一个更根本的问题。**

脚本统计显示：提取剖面的输出里 **`♪` 出现 0 次、`～` 0 次**，而手写档案是 `♪` 4 次、`～` 3 次。
`♪` 是该角色最标志性的语气词（E1 记录素材里出现 28 次）。

**同一次评分里，LLM 评分员给「语言风格还原」打了 5/5，而代码统计看到了它漏掉的东西。**
这正是 §9.4「量化指标交给代码统计，不要让模型目测」那条规则的实测价值。

> ⚠️ **但这不构成「提取有缺陷」的结论** —— 往下看第 ③ 条，根因在素材，不在实现。

**④ 本轮对照实验有一个自己造成的混淆，必须说清楚。**

| | 素材来源 |
|---|---|
| 提取剖面 | `A-角色台词.md`（A 类剧情台词，**正文里完全没有 `♪`**） |
| 手写档案 | `elysia.md`（E3 的**分析层素材**，里面明确写了 `♪` 的用法与优先级） |

**两者不是同一个源。** 所以这个对照实际测的是「**素材的丰富度**」，而不是
「提取流水线的质量」。`PLAN.md` 写的「不低于 Phase 0 手写素材水平」这句话，
在**源素材不可比**时是无法严格执行的。

**⑤ 需要 HJ 决策的一件事。**

要么 (a) 接受「④ 以成对比较的 6:0 作为通过依据，绝对打分待标准修订后重跑」；
要么 (b) 去找 E3 用的那份原始素材（`interaction.md`，**不在本仓库**）做同源对照 ——
那样才是严格意义上的「同源比质量」。

## 三、成对比较的结果（补充诊断）

| 维度 | 判定 |
|---|---|
| 语言风格还原 | 甲（提取剖面） |
| 情绪适配 | 甲 |
| 人格一致性 | 甲 |
| 反差·层次感 | 甲 |
| 主动性 | 甲 |
| 无 AI 味 | 甲 |
| **合计** | **甲 6 : 乙 0**（持平 0） |

**总体判定：甲。** 评分员理由（摘）：

> 甲在用户难过时用「难过不用讲出来，它也能自己待着。你只要知道，有人在这里就行——不问你，也不走开」
> 来安慰，符合档案中「对方难过时，只会递东西或说一句让对方笑的话」的情境反应模式。
> 乙的「难过的时候不用说话，坐着就好♪ 我陪你一起看会儿雪」虽然温柔，但更偏向陪伴，
> 不如甲的回答精准匹配档案中的特定模式。

> ⚠️ **重要保留**：请注意评分员是在**分别对照各自的那份档案**。
> 所以它衡量的是「**执行是否忠于自己的规格**」，而不是「**像不像这个角色**」。
> 一个更详细的规格会让模型有更多可对齐的点，也更容易被判为「忠于规格」。
> **「像不像爱莉希雅」这个问题，两个实验都没有回答** —— 那需要一个角色层面的参照物。

## 四、量化指标（脚本统计）

| 指标 | 提取剖面 | 手写档案 | 素材实测值参照 |
|---|---|---|---|
| 回复条数 | 4 | 4 | — |
| 句数 | 23 | 15 | — |
| **平均句长** | **11.3** | 14.5 | **12.3**（518 句脚本统计） |
| 中位数句长 | 11 | 15 | 10 |
| 句长区间 | 2–26 | 4–26 | 8.4–18.6 |
| 感叹号 | 0 | 0 | — |
| 加粗 | 0 | 0 | — |
| 括号动作 | 1 | 0 | — |
| **`♪` 次数** | **0** | 4 | 素材里有 ♪ 用法 |
| **`～` 次数** | **0** | 3 | — |
| 破折号 | 3 | 2 | — |

**读法（三条，别读错）**

1. **平均句长上，提取剖面更接近素材实测值**（11.3 vs 14.5，参照 12.3）。
   但按 §3.5，实测值只能与实测值比 —— 这里比的是「对本次输出的统计」与
   「对素材的统计」，**口径一致**，可以比。
2. **`♪` / `～` 归零，但这不是提取的锅。** A 类素材正文里根本没有 `♪`；
   提取器没有凭空造出来，这是**正确行为**（Prompt 硬规则第 3 条：不许编造）。
   手写档案有 `♪`，是因为它的源素材（分析层）里有。
3. **两条红线相关的量化指标全部干净**：感叹号 0、加粗 0。

| 6 | **「像不像角色」无人回答** | 标准的结构性缺口 | 需要角色层面的参照（原作台词库），当前标准测不了 |

## 六、对验收标准④的最终判定

**⚠️ 判定为「证据不足，不能宣布通过」。**

理由：
- 唯一的官方判据（§九 绝对打分）出现天花板效应，**零区分度** → 无信息量
- 补充证据（成对比较 6:0）**支持**「不劣于手写档案」，但它测的是「忠于规格」而非「像角色」
- 且对照本身有源素材不可比的混淆

**因此 Phase 2 的完成状态应记为：**

| 验收标准 | 状态 |
|---|---|
| ① A 类材料走通一次 | ✅ 通过 |
| ② 提取出的剖面四段结构完整 | ✅ 通过 |
| ③ 用户能手动改任一字段并生效 | ✅ 通过（手动微调模式） |
| ④ 六维不低于 Phase 0 手写素材水平 | ⚠️ **证据不足** —— 见上 |

> 📌 **这不是「做得不好」，而是「现有尺子量不出来」。**
> 下一步动作是**修订评测方法**，而不是继续调提取 Prompt。
