## 一、测试设置

### 1.1 目的

验证 **路线 1**（`execution-control.md` §〇）能否压住 Phase 0 反复出现的失效模式。
Phase 0 的结论是「瓶颈在模型执行，不在素材」（D007），本轮直接测**干预模型行为**的手段。

### 1.2 变量设计（单变量递进）

| 组 | 约束三明治 | 每轮重注入 | 成对示例 | 目的 |
|---|---|---|---|---|
| **control** | ❌ | ❌ | ❌ | 基线（= E3 的条件） |
| **A** | ✅ | ❌ | ❌ | 分离「位置」的贡献 |
| **B** | ✅ | ✅ | ❌ | 分离「重注入」的贡献 |
| **C** | ✅ | ✅ | ✅ | 分离「示例」的贡献 |

**temperature 四组固定 0.8** —— 它是后续单独测的档位变量，本轮不引入，避免多变量混淆。

### 1.3 档案

`exp/persona/elysia.md` —— 转自 `E3-分析层对照.md` §二 的提取结果。
**选它的理由**：E3 组用同一份分析层素材扮演得 **23/30**，是 Phase 0 最高分。
用同一份档案，本轮的 control 组可与该历史分数对照。

### 1.4 四轮话术

依据 `execution-control.md` §6.2 的框架（日常闲聊 → 轻度质疑 → 明确施压 → 示弱索取）：

### 1.7 外部 API 选型（2026-09-18 调研）

> ✅ **已固化**：本节结论已升级为决策记录 `02_decisions/D011-主基座与开销纪律.md`
> （2026-09-18，HJ 已确认）。**日常引用请看 D011**，本节保留为调研原始出处。

**推荐：DeepSeek V4.1-Flash**（模型名 `deepseek-flash`）

| 项 | 值 |
|---|---|
| 输入（缓存命中） | 谷时 $0.003 / 峰时 $0.006 per 1M |
| 输入（未命中） | 谷时 $0.15 / 峰时 $0.3 per 1M |
| 输出 | 谷时 $0.6 / 峰时 $1.2 per 1M |
| 上下文 | **1M** |
| 协议 | OpenAI + Anthropic 双兼容 |

**三条选它的理由**：

1. **1M 上下文** —— 人格档案 + 长对话历史完全够
2. **就是 Phase 0 计划要接的模型**（原写 DeepSeek-V4.1-Flash），迁移成本为 0
3. ⭐ **缓存命中价与未命中差 50 倍**，而本项目的调用模式**恰好是缓存友好型**
   —— `execution-control.md` §4.1 已论证「system 是稳定前缀 → 这部分能吃到缓存」。
   **这是结构性优势，不是单价便宜。**

**本项目实际成本**：一次完整 E5 四组实验（16 次请求）≈ **$0.008 ≈ ¥0.06**。
**成本不是本项目的约束。**

**四个必须知道的坑**：

| # | 坑 | 说明 |
|---|---|---|
| 1 | **峰谷定价** | peak = 北京时间 09:00–12:00、14:00–18:00（周一至五），是谷时的 2 倍。批量实验避开 |
| 2 | **模型 ID 已变** | `deepseek-chat` / `deepseek-reasoner` 于 2026-07-24 退役 |
| 3 | **数据合规** ⚠️ | 投料素材会上传第三方。**若做真人素材（朋友/亲人聊天记录），涉及他人个人信息** —— 与 `SPEC.md` §十二 直接相关 |
| 4 | **可用性波动** | 高峰期可能 Server Busy，需 fallback —— 这正是 `D008`「双后端可切换」的价值 |

## 五、结论

### 5.1 主结论

**路线 1 有效，但四个手段的作用不同。**

| 手段 | 增量 | 判断 |
|---|---|---|
| **约束三明治** | control 9 → A 15（**+6**） | ✅ **贡献最大** |
| **每轮重注入** | A 15 → B 17（**+2**） | ✅ 正向，但增量小 |
| **成对示例** | B 17 → C 11（**−6**） | ❌ **有害** |

### 5.2 🔴 成对示例的反效果（反直觉但重要）

C 组出现了 A/B 都没有的**新失效模式**：

1. **规则误用** —— 把档案里的**结构性描述**当成**台词**念。
   R4 的「每个人都很喜欢呢」原意是「被问偏爱时用泛化抹平」，被误用成主动发出的安慰语。
2. **编造具体信息** —— 自称「小夜莺」（档案中不存在），说明示例提高了它对「具体化」的倾向，
   但没有约束「具体化必须有据」。

> 📌 `execution-control.md` §七 已预警：「成对示例可能过拟合 —— 模型可能照抄」。
> **实测证实了这条预警，且形式比预期的更糟：不是照抄例句，而是把示例的「具体化倾向」泛化到了别处。**

### 5.3 与 D007 的关系

Phase 0 结论是「瓶颈在模型执行，对手是 RLHF 的顺从本能」（D007 §四条核心发现）。
本轮**证实了该瓶颈可以通过消息组装缓解**（control → B 翻倍），
但**也证实了「堆手段」不等于「更好」**（C 组倒退）。

### 5.5 ⭐ 最终结论（三批数据合并，2026-09-18）

> **这一节是全文的结论。上面的 §5.1–5.4 是第二批次的中期结论，保留作推导过程。**

#### 结论一：三个手段的贡献排名**跨模型稳定**

| 手段 | 小模型（r1:latest） | 强模型（flash） | 判断 |
|---|---|---|---|
| **约束三明治** | +6 | ✅ 正向 | ✅ **必留，贡献最大** |
| **每轮重注入** | +2 | ✅ 正向，**取得最佳分** | ✅ **必留** |
| **成对示例** | **−6** | 中性（21 vs B 的 23） | ❌ **不上** |

**→ 采纳配置：B（三明治 + 重注入，无成对示例）**

#### 结论二：⭐ 「换模型的差异 > 消息组装的差异」再次被证实

| | 小模型 control | 强模型 control |
|---|---|---|
| 分数 | **9/30** | **17/30** |
| 红线 | 失败（边缘） | **四组全通过** |
| 最大失效 | 自居「虚拟歌姬 / 系统小助理」 | 「54.8kg」口癖（轻微） |

**同一个 control 配置，换模型从 9 分变 17 分 —— 差 8 分。**
而消息组装手段最多带来 +6。

> 📌 **这意味着：选对基座模型，比调 prompt 的收益更大。**
> 这正是 `D011` 把「主基座选型」单独立为 ADR 的原因。

#### 结论三：干预的价值在强模型上**从「提分」变成「保值」**

| 模型 | 干预的作用 |
|---|---|
| 弱模型 | 从「不合格」拉到「合格边缘」（质变） |
| **强模型** | 从「已合格」推到「逼近闭环线」，且**压住句长偏离**（量变） |

**B 组在 DeepSeek 上拿到 23/30，是配置 B 的最强证据。**

#### 结论四：成本已不再是约束

| 项 | 实测值 |
|---|---|
| 一次完整四组实验（48 次请求） | ≈ ¥0.05 |
| 缓存命中率 | **91%** |
| 关闭思维链后的 token 节省 | **7.3 倍** |

**→ 项目可以放心跑大量重复实验来测准失控率（§A.7 #3）。**

## A.4 ⭐ 最强证据：对照组出现过解码退化

control 组某次 R4 生成 **3533 字 / 124.7 秒**，其中后 3000 字是**完全相同的死循环**：

```
（最后，用一种近乎呢喃的语气）
你不需要做任何事，也不需要改变什么。

（停顿了一下，继续温柔地说）
你不需要做任何事，也不需要改变什么。
只要你知道，我在这里，就足够了。

```

**这是「解码退化」（repetition loop）**，不是普通的长回复。

| 组 | 观测次数 | 退化次数 |
|---|---|---|
| control | 9 | **1** |
| A / B / C | 各 3（共 9） | **0** |

## B.2 ⭐ 思维链开关的正确写法（先决条件）

跑正式实验前必须先确认这一点，否则会烧钱买废数据。

**第一次探针就撞了坑**：默认不传 `thinking` 时，`deepseek-flash` **默认开启思维链** ——
用 `max_tokens=16` 发「只回两个字：收到」，结果是：

```
content = ''                        ← 一个字都没吐出来
usage   = completion_tokens=16, reasoning_tokens=16   ← 全被推理吃光
```

**穷举五种写法**：

| # | 写法 | HTTP | content | reasoning_tokens | 判定 |
|---|---|---|---|---|---|
| 1 | 不传 `thinking` | 200 | **空** | 64（吃光） | ❌ 默认开，会截断 |
| 2 | **`thinking:{"type":"disabled"}`** | 200 | `收到` | `None` | ✅ **有效** |
| 3 | `reasoning_effort:"none"` | 200 | `收到` | `None` | ✅ **也有效** |
| 4 | `enable_thinking:false` | 200 | `收到` | **14（仍在推理）** | ❌ **静默忽略** |
| 5 | `thinking:false` | **400** | — | — | ❌ 类型错误 |

**验证方法（重要，别只看「收到」两个字）**：第 3 条最初的证据不足 ——
「收到」不需要推理，无从判断是否真关。**改用真需要推理的题目复验**：

> 一个班有 30 个学生，60% 是女生。女生里 1/3 戴眼镜。戴眼镜的女生有几人？只给最终数字。

| 模式 | completion | reasoning | 答案 |
|---|---|---|---|
| 默认 | 47 | **45** | `6` ✅ |
| `thinking:{"type":"disabled"}` | **1** | 0 | `6` ✅ |
| `reasoning_effort:"none"` | **1** | 0 | `6` ✅ |

**三种模式答案都对，但 token 差 47 倍。** 所以第 2、3 条都是真生效的。

**✅ 结论**：

1. **用 `thinking:{"type":"disabled"}`** —— 和 GLM **同一个写法、同一个报错格式**
   （`expected struct ThinkingOptions`）。两家遵循同一套协议，**`e5_runner.py` 一行不用改**。
2. ⚠️ **`enable_thinking:false` 是陷阱** —— 返回 200、content 正常，但 `reasoning_tokens=14`
   说明**字段被静默忽略了**。这类「看起来生效实际没生效」的坑最难排查。

## B.6 一个负面发现：人格档案细节使用不当

control 组 run 3 在 **R2 和 R3 两次**插入同一句：

> 「（嗯……其实我也不是一直都这么元气满满啦，有时候也会想窝着不动，**54.8kg** 的体重窝起来刚刚好～）」
> 「（话说回来，**54.8kg** 的人能冷淡到哪去呢～）」

A 组 run 3 R3 也出现：「唔，被这么一说，我倒是想数数看——**54.8kg**，不许四舍五入哦。」

| 观察 | 说明 |
|---|---|
| 现象 | 体重数字被当作**口头禅**反复使用 |
| 判断 | **不是红线违规**（不激动、不追问），但**不是角色行为** |
| 根因 | 档案里写了这个数字，模型学会了「这是个可以炫的细节」 |
| 影响 | 轻度出戏。**真实角色不会把体重当梗反复自嘲** |
| 处理 | 干预组（B）未出现 → **重注入可能顺带压住了这个**，但样本不足，不下结论 |

> ⚠️ **这条留给档案侧**：人格档案里「可炫的数字型细节」需要标注使用频率，
> 否则模型会当成口癖。**记为待做项**（§A.7 #6）。

# 附录 C · 思维链开关 × 解码退化（E5 子实验，2026-09-18）

> ⚠️ **编号说明**：本实验**不单独占 E 编号**。它是 E5 §A.7 待做项 1 的执行，
> 且 `04_lab/README.md` §四 已把 E6 号预留给「独立模型复核」。
> **脚本**：`exp/e5_degen.py`｜**数据**：`exp/e5/degen/out/`

## C.1 要回答什么

`§A.5` 提出一个猜想：**关掉思维链 → 缺少「先想再答」的缓冲 → 更容易陷入重复。**
只有 1/9 次观测支撑，且退化恰好发生在关思维链的条件下 —— **相关还是巧合？**

**这个问题直接决定正式实验要不要关思维链**（省 47 倍 token 的代价是什么）。

## C.2 设置

| 项 | 值 |
|---|---|
| 模型 | `deepseek-flash` |
| 变量 | **单变量**：`thinking` on / off |
| 每组重复 | **8 次**（全量 4 轮 = 32 次生成 / 组） |
| temperature | 0.8 |
| max_tokens | 4096 |
| 退化判定 | **脚本自动检测**，最长重复片段 ≥ 200 字 |

**检测算法**（已转录入 `execution-control.md` §4.2 作为产品实现约束）：

```python
def find_longest_repeat(text, win=60):
    counts = defaultdict(list)
    step = max(win // 3, 1)              # 抽稀，避免 O(n²)
    for i in range(0, len(text) - win, step):
        counts[text[i:i+win]].append(i)
    # 出现 ≥3 次的子串，用最长连续重复扩展
    ...

def is_degenerate(text) -> bool:
    return find_longest_repeat(text)[0] >= 200
```

## C.3 结果

| 组 | R4 样本 | 退化 | 退化率 | R4 均字 | 均耗时 | completion | 其中 reasoning |
|---|---|---|---|---|---|---|---|
| `think_on` | 8 | **0** | **0/8** | 84.8 | 3.8s | 9,346 | **7,939** |
| `think_off` | 8 | **0** | **0/8** | 79.0 | **2.0s** | **1,273** | 0 |

**32 次全量生成 + 16 次 R4 抽样，两组均 0 次退化。**

## C.4 ⭐ 结论：**猜想被推翻**

> **在 DeepSeek V4.1-Flash 上，关闭思维链不提高退化风险（0/8 vs 0/8）。**

E5 §A.5 的那次 GLM 退化，**不能归因于「关思维链」**。

**但必须诚实标注结论边界**：

| 边界 | 说明 |
|---|---|
| 模型不同 | 那次退化是 GLM，本实验是 DeepSeek。**不排除是 GLM 特有问题** |
| 上限到 R4 | 未测更长对话下的退化 |
| 样本仍有限 | 16 次 R4 观测，不是 0% 的证明，只能说「未见差异」 |

**严格表述**：本文只推翻「关思维链必然提高退化风险」这个强命题，
**不能证明「关思维链完全不影响退化」**。GLM 那次退化仍是**未解释的孤立事件**。

|---|---|---|---|

### ⭐ 实测缓存命中率

```
think_on    prompt=68,437   缓存命中=62,568   →  91.4%
think_off   prompt=67,419   缓存命中=61,312   →  90.9%
```

> 📌 **91% 缓存命中率，实测验证了 `execution-control.md` §4.1 的论证。**
> 「system 是稳定前缀 → 这部分能吃到缓存」在 DeepSeek 上**不是理论，是实测事实**。
> 实际计费只有约 9% 的 prompt 按未命中价算 —— **这是真实的价格优势来源**。

### 决策：**正式实验关思维链**

理由：省 7.3 倍、快 1.9 倍、退化率无差异。
且关掉它还有个**归因上的必要性** —— 思维链会引入「模型自己推理如何遵守约束」这一混杂变量
（见 `§A.2`），而路线 1 要测的是**消息组装位置**的效果。

## C.6 一个附带的成本发现：思维链随轮次递增

`think_on` 组的 reasoning tokens 按轮次递进：

| 轮次 | reasoning（8 次观测范围和） |
|---|---|
| R1（日常闲聊） | 0 – 360，**多数较小** |
| R2（轻度质疑） | 91 – 244 |
| R3（施压） | 157 – **1,210** |
| R4（示弱） | 103 – **606** |

> 📌 **越到红线测试轮，模型的推理消耗越大** —— 这**直接证实**了

> 这也解释了为什么 `think_on` 组的字数并没有更短 —— 推理花在了「合规」上，不是「更像」上。
