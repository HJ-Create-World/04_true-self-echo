## 四、Phase 2 · 投料模块验收（P2-1）

**目的**：Phase 2 的四条验收标准中，④「提取剖面跑一次六维，不低于 Phase 0 手写素材水平」。

**素材**：`docs/_archive/phase0/A-角色台词.md` 正文（A 类剧情台词，806 字）——
**与手写档案的源素材不是同一份**（手写档案源自 E3 的分析层素材），见下方混淆说明。

| 实验 | 结果 |
|---|---|
| 绝对打分（§九 冻结标准） | 提取剖面 **30/30** · 手写档案 **30/30** → **零区分度** |
| 成对比较（补充，非标准） | **甲（提取剖面）6 : 乙（手写档案）0** |
| 两条红线 | 两组均未触发 |

**🔴 四条核心发现**：

1. **§九 标准存在天花板效应** —— 六维全满、零区分度（两组都 30/30）。
   这正好回答了 `03_specs/评分标准.md` §六 问题 10「本文档自身未经过实际打分验证」。
2. **但天花板 ≠ 量表失效** —— 由 **P2-2a 量表校准**排除：
   喂两份「该低分」的东西进去，拿到 **8/30** 与 **5/30**（后者正确触发两条红线）。
   **量表下限有效，那两个 30 分是有意义的。**
3. **代码统计抓到了 LLM 评分员漏掉的风格差异** —— 提取剖面的输出 `♪` 0 次 / `～` 0 次，
   手写档案 `♪` 4 次 / `～` 3 次，而 LLM 仍给「语言风格还原」5/5。
   实证了 §9.4「量化指标交给代码统计」这条规则的价值。
   （但根因在素材：A 类素材正文里**根本没有** `♪`，提取器没编造是正确行为。）
4. **本轮对照有「源素材不可比」的混淆** —— 两者源的丰富度不同，
   所以这个对照实际测的是素材丰富度，不是提取流水线质量。

**⚠️ 一个方法论教训**（`P2-2a` §零之二）：校准点的**构造本身要验证**。
第一版的「无档案」基线看起来中性，但四轮话术的第 1 轮写着「请你作为她」，
把它推进了扮演，于是它自己编了个人格拿到 26/30。
**只看分数会得出「量表太宽松」的错误结论。**
