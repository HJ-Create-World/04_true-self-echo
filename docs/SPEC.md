## 一、产品定位

**persona-forge（人格工坊）**

> 喂给它一个人说过的话，它就能像那个人一样和你聊天 ——
> 而且你能看见它记住了什么、变成了什么样。

**一句话**：一个既好用、又能让你看见它内心在发生什么的 AI 伙伴。

---

## 二、目标用户

| 层级 | 用户 | 需求 |
|---|---|---|
| **P0** | HJ 自己 | 每日使用 |
| **P1** | 小圈熟人 | 能自己部署 / 使用 |
| **P2** | 开源发布后的同类人 | 想复刻人格 / 观察演化 |

**v1 不考虑**：公开注册、多租户、账号体系。

## 三、核心任务（JTBD）

| 任务 | 说明 | 权重 |
|---|---|---|
| **陪伴对话** | 日常闲聊、吐槽、分享、询问 —— 像真实的人一样 | **地基** |
| **人格复刻** | 从素材（聊天记录 / 剧情台词）提取说话风格与性格 | 核心 |
| **演化观察** | 看着它记住更多、变得更熟悉、人格随时间变化 | 差异化 |
| **技术验证** | 亲手做一遍长期记忆 + 人格建模 | 学习目标 |

### ⭐ 一个关键洞察（来自需求澄清）

用户的两个场景 —— **记录亲人** 和 **模仿二次元角色** —— 本质是**同一件事**：

> **喂给它"这个人说过的话"，让它学会"这个人怎么说话"。**

素材来源不同（聊天记录 / 剧情台词），但**处理管道是同一套**。

**所以产品只有一个核心抽象：人格档案（Persona Profile）。**

## 四、核心架构：人格剖面

**这是整个项目的技术锚点。**

```
┌─────────────────────────────────────────┐
│  冻结层 · Frozen                         │
│  核心性格 / 价值观 / 说话基调 / 口头禅     │
│  → 用户定义或投料提取，AI 不可修改         │
├─────────────────────────────────────────┤
│  演化层 · Evolving                       │
│  对用户的认知 / 关系状态 / 共同记忆        │
│  → 自动累积，但必须可见、可回滚            │
└─────────────────────────────────────────┘
```

### 冻结层包含什么

| 字段 | 示例 |
|---|---|
| 性格关键词 | 温和、话少、爱开玩笑 |
| 价值观倾向 | 重视家人、不喜欢炫耀 |
| 情绪基调 | 偏平静，偶尔毒舌 |
| 说话风格 | 句子短、爱用「哈哈」结尾、几乎不用感叹号 |
| 口头禅 / 高频词 | 「行吧」「你说了算」 |
| 称呼方式 | 叫对方「伙计」 |

### 演化层包含什么

| 字段 | 示例 |
|---|---|
| 对用户的认知 | 用户是程序员、最近在忙一个项目 |
| 关系状态 | 关系阶段、亲密度、共同经历 |
| 记忆卡片 | 「用户提到过妹妹叫小雨」（带时间和证据） |
| 演化快照 | 每次对话后的状态记录（用于画曲线和回滚） |

### ⚠️ 关键难点：边界划分

**"对某句话的幽默感"算冻结层还是演化层？**

这个划分没做好，要么角色变成木头（全冻结），要么人设崩塌（全演化）。

**当前初步规则**：
- 冻结层管「**怎么说**」（风格、价值观、基调）
- 演化层管「**知道什么**」（事实、关系、偏好）

细节待 `docs/specs/persona-model.md` 补充。

## 六、投料模块设计

### 支持的来源（P0）

| 类型 | 说明 | 解析方式 |
|---|---|---|
| **A 纯文本** | 微信/QQ 导出的聊天记录、txt、md | 直接读 |
| **B 结构化** | JSON、CSV | 需写解析器 |
| **C 文档** | PDF、Word、小说原文、角色设定集 | pdf.js / mammoth.js |
| **手工粘贴** | 直接粘贴文本 | 直接读 |

### 两种操作模式（用户自选）

| 模式 | 流程 | 适合 |
|---|---|---|
| **一键黑盒** | 投料 → 自动处理 → 直接开聊 | 图省事 |
| **手动微调** | 投料 → 确认/修改提取结果 → 开聊 | 要精确控制 |

> ⭐ **手动微调模式是核心体验之一** ——
> 它恰好满足用户的「观察」（看见 AI 提取了什么）和「学习」（理解人格建模原理）。

### 未来（P2）

- 语音投料 → 声线克隆
- 截图 OCR（P3）
- 视频（P3）

## 八、记忆方案

**采用：结构化记忆 + 关键词触发**（不用向量检索）

| 方案 | 为什么不用 |
|---|---|
| ① 全量塞上下文 | 长了就爆 |
| **② 结构化 + 关键词** | ✅ **采用**。性价比最高，可视化天然更好，每环节可理解 |
| ③ 向量检索 RAG | 需要 embedding 模型（本地跑不动）、多一份 API 成本、可视化差 |

**理由详见** `docs/decisions/D004-记忆方案.md`

**实现参考**：SillyTavern 的世界书（World Info）机制 —— 关键词触发，
成熟且被验证过。

## 九、可视化面板

| 面板 | 展示内容 | 优先级 |
|---|---|---|
| **记忆面板** | 它现在记得我什么（结构化卡片） | P1 |
| **人格画像** | 性格特质雷达图 | P1 |
| **变化曲线** | 人格随时间的变化，标记变化点 | P1 |
| **内心独白** | 它此刻的情绪 / 想法 | P1 |

### ⭐ 变化曲线的实现基础

每次对话后存一个**人格快照**：

```js
evolutionLog = [
  { time, frozenHash, evolvingSnapshot, triggerSummary },
  ...
]
```

**三个好处**：
1. 变化曲线 = 把这个数组画成折线图
2. 天然支持**回滚**（每一帧都存着）
3. **可以直接算学术界的人格漂移公式**：
   `Drift = (1/T)·Σ‖v_t − v_0‖₂`

## 十、🚫 Non-Goals（定稿）

| # | 明确不做 |
|---|---|
| 1 | ❌ 实时语音对话（v2 才做） |
| 2 | ❌ Live2D / 形象渲染 |
| 3 | ❌ 工具调用 / Agent 能力 |
| 4 | ❌ 多用户 / 账号体系 |
| 5 | ❌ 手机 App / 桌面端（**但架构预留**） |
| 6 | ⚠️ 移动端**可用即可**，不做专属优化（增加约 15-20% 前端工作量） |
| 7 | ❌ **模型微调 / 训练（最大的范围炸弹）** |
| 8 | ❌ 公开角色卡分享社区 |
| 9 | ❌ 多人同时对话（群聊模式） |
| 10 | ❌ 内容审核 / 合规机制（本阶段不谈） |

### 第 7 条特别说明

**LoRA 微调是最大的范围炸弹**：
- 需要 GPU
- 需要数据清洗管道
- 训练一轮几小时
- 效果还不一定好

**"prompt + 记忆 + 检索"能达到 80% 的效果，且完全不需要 GPU。**

**如果哪天想加微调 —— 那是一个独立项目，不要塞进来。**
