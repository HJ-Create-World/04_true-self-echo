## 三、⭐ 三个关键问题的正面回答

### 问题 1：有没有产品做「人格演化可视化」？

**答：产品侧没有，学术侧有。**

| 层面 | 状况 |
|---|---|
| **商业产品** | Character.AI / Replika / 星野 / SillyTavern / Janitor / Chub / NovelAI —— **全部没有**人格版本、时间线、回滚 |
| SillyTavern（最接近） | 只有**整库文件备份**，恢复是全量覆盖，**不是版本控制** |
| **学术侧** | CharacterGPT 论文（arXiv 2405.19778）明确支持"与某时间点的角色对话"；`likenneth/persona_drift` **已经把漂移曲线画出来了** |

> **结论：技术上被验证过，工程上没人做成产品。**
> 这既是机会（位置空着），也是警告（**空着可能是有原因的**，见问题 3）。

### 问题 2：有没有产品做「真人风格模仿」且合规活着？

**答：有，但都在收紧。**

中国的《人工智能拟人化互动服务管理暂行办法》带来了明确约束（详见第四节）。规避方式主要是：
- 转向**虚构角色**（不做真实人物）
- 或定位为**本地工具**而非公开服务

### 问题 3：用户为哪些功能付费？

| 产品 | 付费点 |
|---|---|
| Character.AI | 订阅制（跳过排队、更快响应） |
| Replika | Pro 订阅（亲密互动、语音） |
| 星野 | 内购（角色卡、好感度道具） |

⚠️ **关键**：**没有找到任何产品靠"人格可视化/版本管理"收费。**
付费点集中在**对话质量**和**亲密互动**上，而非工具性功能。

## 四、⚠️ 合规红线（必须记录）

### 《人工智能拟人化互动服务管理暂行办法》

| 项 | 内容 |
|---|---|
| 发布 | 五部门联合，2026-04-10 公布 |
| **施行** | **2026-07-15 已施行** |
| 地位 | 全球首部专门针对**情感陪伴型 AI** 的国家级法规 |

### 判定三要素（逐条命中我们的场景）

1. 是否塑造**稳定人格** → ✅ 我们就是在做人格档案
2. 是否**保存长期记忆延续关系** → ✅ 演化层就是做这个
3. 是否**以陪伴亲密关系维持使用** → ✅ 陪伴是产品地基

> **三个场景逐条命中监管范围。**

### 红线条款

| 条款 | 影响 |
|---|---|
| 不得向未成年人提供虚拟亲属/伴侣 | 用户限制 |
| **不得过度迎合、诱导情感依赖** | ⚠️ 与陪伴场景天然冲突 |
| 不得情感操纵 | |
| **AI 身份标识**（不能藏协议里） | 必做义务 |
| **依赖预警弹窗** | 必做义务 |
| **连续使用每超 2 小时提醒** | 必做义务 |
| 安全评估 + 算法备案 | 若公开服务 |

### 两个之前没注意到的细节

1. **逝者生前明示意愿优先于近亲属决定** —— 不是家属同意就行
2. **「不得诱导情感依赖」是硬条款**，而陪伴场景天然指向情感依赖

### 政策鼓励方向（可能是机会）

> **「探索开展电子签名授权应用研究」**（生前授权）

→ 如果是"生前明确授权"的数字化，合规路径可能更清晰。**这是个值得跟踪的空白。**

## 五、🔴 最重要的一条冷水

### 用户抱怨排名：过滤 > 记忆丢失

**用户想要的是「别忘、别变扁平」，不是「把变化画出来」。**

| 证据 | 说明 |
|---|---|
| Character.AI 社区高频词 | `personality drift` / `character decay` / **`lobotomized`**（脑叶切除） |
| Replika 2.0 换记忆架构 | 导致多年人格空白，**社区暴动** |
| 星野用户真实动作 | **移动硬盘备份 + 迁移到 SillyTavern** |

**用户的真实诉求是「保命」，不需要时间线图。**

> ### 结论：定位顺序要调整
>
> - **「可回滚」是证明手段，不是产品卖点**
> - **「人格不会漂」才是入口**
> - 叙事应该是："我们保证它不会变成另一个人 —— 就算变了，你也能一键回到昨天"

### 附带发现：用户已经在用我们的术语

`personality drift` / `character decay` 是用户的**自发用语**。
→ **这是产品命名和叙事的现成语言，可以直接复用。**

## 六、差异化判断

| 判断 | 结论 |
|---|---|
| 「人格演化可视化 + 回滚」 | **真空白**（产品侧）但**伪空白感**（学术侧早做了，空着可能有原因） |
| 定位建议 | **SillyTavern 插件 / 伴生工具**，而非替代品 |

**为什么选插件形态**：

| 理由 | 说明 |
|---|---|
| 生态开放 | SillyTavern 33k★、300+ 贡献者 |
| 避开合规正面战场 | 不做公开服务，不做内容分发 |
| 聚焦差异化 | 我们只做"人格版本管理"这一件事 |
| 降低推广门槛 | 蹭现成生态的用户 |

### 最容易死的三个点

| # | 死因 | 应对 |
|---|---|---|
| 1 | **做出来的东西"很酷但没人用"** —— 因为用户要的是"别变"不是"看它变" | 叙事转向"稳定性保证" |
| 2 | **合规风险** —— 三个场景逐条命中 | 避开真人复刻；纯本地可导出 |
| 3 | **范围蔓延** —— 又想做人格管理、又想自己做对话前端、又想接语音 | 严格 Non-Goals，只做插件 |
