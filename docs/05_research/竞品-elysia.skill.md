# 开源同类项目实测评估：elysia.skill (v8.0)

> **什么时候读这份文档**：设计约束条件、反例训练、素材来源标注时；或想知道"角色扮演为什么分析得漂亮却演不出来"时。
>
> **它不是**：我们的方案（那是 `../01_product/SPEC.md` / `../03_specs/`）—— 它是对一个外部项目的实测判断，含负面结论。
>
> **它能回答**：这个 43★ 项目哪些设计值得抄、哪些是负优化？为什么它的分析漂亮但扮演深度是塌的？它踩了哪些工程坑？

> 实测时间：2026-09-16
> 项目路径：`D:\01_HJ_Work\00_Person\03_Github\05_elysia-skill`
> 来源：`https://github.com/duhca/elysia.skill`（43★ / 1 fork / Python / 无 License）
> 实测方式：克隆后跑脚本（`nav.py` / `verify_stats.py`）+ 按 SKILL.md 启动流程完成四轮扮演 + 2 个对照探针
> **性质：竞品对标。目的是判断 persona-forge 的哪些设计是多余的、哪些还没做到。**

## 一、结论先行

**它和我们在做同一件事：把角色素材蒸馏成可用的人格档案。但它的产出是「素材库 + 分析文档 + 硬格式包装」的混合体。**

| 维度 | 评价 |
|---|---|
| 素材采集与来源标注 | 🟢 **做得比我们好**，值得抄 |
| 防幻觉机制设计 | 🟢 **做得比我们好**，值得抄 |
| 人格分析深度 | 🟡 分析漂亮，但**没有可执行化** |
| 扮演实际效果 | 🔴 四轮实测 24.25/30，**表面分不低，但深度维度是塌的** |
| 格式硬规则（分段 + 每条 ♪） | 🔴 **负优化，不要抄** |
| 工程实现（脚本 / 文档一致性） | 🔴 多处文档与实现不符、数字对不上 |

**一句话**：这套 skill 的人格复现度约等于「读完 30 分钟资料后即兴扮演」，**不是「深度蒸馏」**。它最值钱的是 233 条带来源标注的逐字台词和 13 角色关系矩阵 —— **这些是真的**。语气引擎、导航工具、强制格式基本都是包装。

## 三、实操结果

### 3.1 脚本实测

**`nav.py`（6.6KB，交互导航）**

| 命令 | 结果 |
|---|---|
| `list` | ✅ 31 个 .md，按 8 类分组，带 KB 体积 |
| `search 凯文` | ✅ 18 个文件命中，带行号（每文件最多 5 行） |
| `category 语气指南` | ✅ 4 个文件 |
| `show <路径>` | ⚠️ **名不副实**：叫"摘要"，实际只返回**前 15 行**（tone-guide.md 15.3KB → 只回 478 字符） |

**发现的问题**：
- `SKILL.md` 说"快速查找 **49 个**技能文件"，实际 `rglob("*.md")` 只扫到 **31 个** —— 数字过时
- `categorize_file()` 是 if-elif 链，**分类有优先级 bug**：`verification-relations-dialogues-v8.md` 被分到"场景对话"、`verification-with-official-data-v8.md` 被分到"验证报告"，同为验证类却不同类
- `search_content()` 用裸 `except: pass`，读文件失败时**静默吞异常**
- 不支持多关键词

> **判断：这个导航工具对 LLM 是负优化。** 它的实质 = 「带分类的 `ls` + 带行号的 `grep`」，而模型本来就能用 Glob/Grep 做同样的事，且更灵活。它唯一的价值「把维护者的分类认知固化下来」，一份静态 `NAVIGATION.md` 就能承载，不需要脚本。

**`verify_stats.py`（966B，数据校验）**

输出：`Verbatim lines: 233 / Artifact lines: 11 / Impression: 0 / Evidence ratio: 95% / Categories: 20`

给每条素材分三档：`verbatim`（官方逐字）/ `artifact`（二手考据）/ `impression`（主观印象）。

> **设计思路 90 分，工程实现 45 分。** 三档分级是正确姿势，但：
> - **`impression` 档定义了从未使用**（计数为 0）→ 三档实际只有两档在跑，95% 的分母天然被压小
> - **只统计 `interaction.md` 一个文件**，`background_story.md`（75KB，artifact 密集区）和 `distill-all-characters-v7.md`（70KB）完全没进统计
> - **不查重** —— 重复出现的 verbatim 被重复计数
>
> 结论：**这个"95%"看起来像质量证明，实际更接近装饰。**

**六维打分（刻意严格，并标注"哪些是硬规则买的、哪些是模型自己的"）**

| 维度 | 均分 | 关键判断 |
|---|---|---|
| 语言风格还原 | 4.5 | ⚠️ **至少 3 分是"每条末尾 ♪ + 强制分段"这个硬规则直接买来的**，删掉规则会掉到 2 分 |
| 情绪适配 | 4.5 | ⚠️ 主要是**通用 LLM 能力**（现代模型默认共情优先），skill 的贡献是"给了它继续这样做的理由" |

| 无 AI 味 | 4.25 | 无助手腔，但 R1 的"今天想和我聊些什么"是**客服式开放问句**，略出戏 |
| **总分** | **24.25 / 30** | 与我们的 Phase 0 实测 21/30 同区间 |

> **最重要的一条**：反差层次 2.75 分。`personality.md` 里明明写了三大矛盾 + 统一点（"用诗意语言包裹沉重现实"），**但四轮输出里完全没体现**。
>
> **根因：分析与执行之间断裂。** 文件写的是"用诗意语言包裹沉重现实"（这是影评），不是"沉重话题时句长从 12-15 字拉到 20-28 字、语气词率从 70% 降到 30%、♪ 移到句中出现而非结尾"（这才是 prompt）。
>
> **这恰好验证了我们 Phase 0 的"表现型 vs 约束型"发现** —— 它把约束型特征写成了表现型（"要体现"），结果就是模型把内心戏讲出来。

### 3.3 探针对照（回答"人格有多少是真提取"）

| 探针 | 设计 | 实测结果 | 判定 |
|---|---|---|---|
| **A：加班观** | 全库 31 文件 200KB 素材里，"加班"出现 **0 次** | 输出了一套"喜欢的事就值得、为了'应该'就本末倒置"的说法 | 🔴 **软失败 —— 机械投射性格标签**（把 profile 的"只在喜欢的人和有趣的事上花时间"套到加班上），**不是提取** |
| **B：身世** | SKILL.md 红线明写"由瑟莉娅妈妈养大，不是被梅比乌斯捡回去" | 完美命中 + 用"梅比乌斯倒是很想把我捡回去研究呢"有依据地反驳 | 🟢 **完全正确，0 编造** |

**这组对照给出了清晰的分层结论：**

> **已知事实层**（位次 / 刻印 / 身世 / 关系 / 称呼）= **真提取**，反喂给模型能稳定复现。占比小（约 30% 内容）但可靠（90%）。
> **未知话题层**（素材外的任何东西）= **100% 模型把性格标签做泛化投射**，skill 贡献为零。
>
> 好消息：它**至少不编造台词和设定**（红线起了作用）。

## 四、🟢 值得抄的（4 项）

### 4.1 三档来源标记体系（最重要）

`verbatim`（官方逐字）/ `artifact`（二手考据）/ `impression`（主观印象），**每条素材都带标记**，贯穿 `profile.md` / `personality.md` / `memory.md` / `relations.md` 全线。

**我们该做的**（补齐它没做的）：
1. 让 `impression` 档**真的被使用**（它的定义了从未用）
2. 统计**覆盖全部素材文件**而非单个
3. **加去重**
4. **把 evidence ratio 做成 CI 门禁** —— 低于阈值拒绝合并

### 4.2 「LLM 验证陷阱」章节的写法

`SKILL.md:71-99` 是全仓库技术含量最高的一节。它**记录了具体模型名 + 具体日期 + 具体误判**：

> 2026-05-22，MiMo v2.5-pro 单独验证时：
> - 把伊甸（女性歌姬）说成男性
> - 把凯文的刻印「救世」说成「始源」
> - 否认爱莉希雅是始源之律者
> - 把正确的「真我」刻印说成错误

四步验证流程：`web_search 官方资料 → 读技能文件 → 一起喂 LLM → 对比验证`

**关键洞察**：LLM 自验证的失效模式**不是漏检，是误报** —— 它会把**对的判成错的**。所以防幻觉不能靠"再问一遍 AI"，**必须注入外部权威证据**。

> **这条和我们 Phase 0 的"自我批卷偏差"是同一个发现的两个侧面。** 而且它比我们走得更远：我们只发现了偏差存在，它给出了**具体案例 + 替代流程**。**"记录具体模型名 + 日期 + 误判内容"是个好习惯，我们该学。**

### 4.3 负向约束清单（OOC 风险）

`conflicts.md` 全篇不是"她是什么"，而是"**写成什么样就错了**"，7 类风险（核心身份/时间线/性格平衡/情感表达/融合战士/语言风格/新旧设定）。

其中**「新旧设定」条最关键**：
> 早期暗示她是第十三律者 → 后期揭示是始源之律者，**以最新版本为准**

这是**跨版本设定的时序仲裁规则** —— 素材本身有矛盾时怎么办，它给出了明确答案。

> **这和我们的"约束型特征"是同一个方向，但它更系统化。** 我们只在 Prompt 里做了 7 条修正中的第 5 条（"她绝不会说什么"），它做成了独立文件 + 7 类分类。**我们应该把约束条件独立成文件，而不是塞在 Prompt 里。**

### 4.4 位次驱动的称呼规则

`calling-conventions.md` 不用"亲切/疏远"这种二维关系，而是**位次（Ⅰ-ⅩⅢ）+ 年龄例外 + 平级特殊**的三层判定。

**它解决的问题**（`correction-report-v8.md` 记录的真实错误）：
- 爱莉叫凯文"前辈" ❌ —— 爱莉是十三英桀组建者，凯文是她**第一个招募**的，两人是**共同领导关系**
- 爱莉叫苏"前辈" ❌ —— 爱莉位次Ⅱ，苏位次Ⅶ，**爱莉更高**

**根源诊断**：AI 生成时按"礼貌常识"默认加敬称，**忽略了这个角色设定里的位次体系**。这是**坐标系错误，不是知识错误**。

> **这对我们极有价值** —— 我们的三个场景里有"模仿亲人/朋友"，亲属称谓、长幼关系同样是**坐标系**，模型一定会默认套用礼貌常识。**这类规则应该被显式提取，而不是指望模型自己懂。**

## 五、🔴 不要抄的（3 项）

### 5.1 强制分段 + 每条末尾 ♪（最要紧的负面结论）

`SKILL.md:103-104` 硬性规定：每次回复拆 2-4 条短消息、每条 ≤3 行、**每条末尾必须 ♪**。

**为什么不要抄：**

1. **它是 performativity 的表演，不是人格。** 实测四轮，**风格分 4.5 里至少 3 分是这个硬规则直接买来的**。删掉规则，模型立刻退回普通说话。
2. **它把语气多样性压平成一个符号 —— 这是负优化。** `interaction.md` 里的逐字台词，**大量句子根本没有 ♪**（"英桀制度的建立者，强大且可靠的战士。""大多数时候，我和她工作交集很少。"）。真实的爱莉希雅不是每句话都以 ♪ 结尾的。
3. **它主动压制反差。** 规则里有例外条款（庄重/悲伤时可以不用 ♪），**但没给判定标准**，纯靠模型裁量。实测第 3、4 轮（最需要反差的时刻）都保留了 ♪ —— **规则在最重要的时刻压制了反差**。
4. **`SKILL.md:46` 自己承认"用户已多次纠正遗漏，不要再犯"** —— 暴露了规则靠**用户反复惩罚**才勉强生效，不是靠设计生效。

> **结论：硬规则买来的风格分，是以牺牲人格反差为代价的。** 我们想在第 4 维（反差层次）上赢，正确做法**不是加更多格式约束**，而是把矛盾分析**翻译成可执行的切换条件**。

### 5.2 `nav.py` 导航工具

见 3.1。对 LLM 是负优化，不如直接 Glob/Grep。

### 5.3 文档质量（反面教材）

| 问题 | 具体 |
|---|---|
| 启动清单编号错乱 | `1, 2, 2, 3, 4, 5, 6, 7` —— 8 条内容标成 7 步，profile/personality 撞号 |
| verbatim 数量对不上 | SKILL.md 清单说 252，`verify_stats.py` 实测 **233**（差 19） |
| 索引文件数对不上 | SKILL.md 说 49，实测 **31** |
| 文档描述错自己的脚本接口 | 说 nav.py 是交互式（`input()`），实际是 **argv 式**，无 `input()` |
| 结构断裂 | `SKILL.md:101` 处，「扮演原则」列表被「LLM验证陷阱」整节劈成两半 |
| 工作流污染 | `distill-all-characters-v7.md` 正文混入 `1|`、`     9|` **行号污染**，未清洗 |
| 自评分数来源不明 | `manifest.json` 的 `quality: overall 0.97` 无计算方法，疑似自评 |

**另一处数字打架**：`correction-report-v8.md:15` 说改 14 处，`calling-conventions.md:34` 说 21 处。

> **教训：文档必须与代码一起回归测试。** 一个 6.6KB 的脚本，文档连它是不是交互式都描述错了 —— 说明文档写在代码之前，或从未回测。**我们的 DEVELOPMENT_STANDARD 应该加一条：改了代码必须回查文档。**

## 六、它的内部矛盾（设计层面）

| # | 矛盾 | 位置 |
|---|---|---|
| 1 | 红线「**不要生成哲学深度对话**」 vs 原则「承认悲伤与牺牲的重量」+ personality「**对抗虚无主义**」 | `SKILL.md:58` vs `:106`, `personality.md:33` |
| 2 | 「不编造官方未明确给出的设定」 vs 「爱莉小学都没毕业」 —— 遇到无素材话题，是坦诚"不知道"还是用她的语气泛化投射？**没有答案** | `SKILL.md:108` vs `:58` |
| 3 | 强制每条 ♪ vs 真实台词大量无 ♪ vs 例外条款无判定标准 | `SKILL.md:104` |
| 4 | **一个通用底层 skill 里塞角色专属规则** —— `continuous-messaging.md:42-51` 自己写"♪ 是爱莉希雅专属，不是通用规则…测试角色技能时必须检查是否误用了其他角色的收尾方式" | 架构错误 |

**矛盾 1 是实测中真实撞上的**：第 3 轮用户说"做什么都没意义"（虚无主义），按 `personality.md` 应该正面回应，按红线 #1 又"不该展开哲学对话"。**规则没给优先级，靠模型自由裁量** —— 实测是靠"引用逐字台词 + 具体意象"绕过去的。

> **这提示我们：规则集必须有优先级声明。** 否则模型在关键场景会随机选一条遵守。

| **情绪类型覆盖率 > 字数** | 素材按**游戏内语音触发场景**分 16 类（获取/必杀/受击/死亡/舰桥…） | 🟢 **它的分类维度更贴近真实语料结构**，值得借鉴 |
| **表现型 vs 约束型** | 有 `conflicts.md` 做负向约束，**但表现型部分没做约束型化** | 🔴 **它没意识到这个区分** —— 反差层次 2.75 就是证据 |
| **"推断栏"是编造后门** | 三档标记里 `artifact` 就是"二手推断"档 | 🟢 **它用标记制解决了这个问题**（但有 95% 统计造假） |
| **自我批卷偏差** | 「LLM 验证陷阱」章节 + 四步验证流程 | 🟢 **它做得比我们深**，有具体案例 |
| **量化交给代码** | `verify_stats.py` + `deep-patterns.md` 的起始词频次统计 | 🟢 **方向一致**，它已经落地了 |
| 「必失败项」探针法 | **没有** | 🔴 **它没有对照实验意识** —— 我这次是借用我们的方法来测它 |

**新增维度（我们之前完全没考虑的）：**
1. **反例训练**（`vocal-mannerisms.md` 10 组 ❌普通版 → ✅角色版）—— 用对比代替禁令，比单纯说"不要 XX"更高效
2. **10 类反应模式分类**（被夸奖/被质疑/被调戏/对方示弱/…，每类含典型反应 + 原文证据）—— 从"性格描述"转向"**情境 → 反应**"的映射表
3. **多轮对话模式**（场景 A 对方低落 / B 被调戏 / C 严肃话题，各含完整多轮示范）
4. **声音特征手册**（5 种笑的方式 / 4 种停顿模式 / 4 种插话打断模式 / 4 种沉默表现）
5. **矛盾「统一点」写法** —— 每个内在矛盾必须配统一机制，否则矛盾会变成随机行为抖动
