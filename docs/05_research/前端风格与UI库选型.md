# 前端风格发现资源与 UI 库选型

> **什么时候读这份文档**：要定 UI 库时；或"知道自己想要什么感觉，但不知道去哪找参考"时。
>
> **它不是**：设计规范本身（那还没有），也不是技术选型决策（决策要另开 ADR）。
>
> **它能回答**：去哪找 UI 风格参考？樱桃粉+珍珠白+淡金这个风格，哪些 Vue3 组件库改得动？
>
> ⚠️ **本文是调研，不是决策。** 选型结论需走 ADR 流程（`DOC_STANDARD.md` §六 模板 1）。

---

## 〇、结论先行

1. **「找风格」和「选组件库」是两个独立问题，不要混做。** 找风格去灵感站（Mobbin / Refero / Recent），选库看主题定制能力。先定风格，再选库 —— 反过来会被库的默认视觉绑架。
2. **这个项目的风格（樱桃粉+珍珠白+淡金+水晶质感）不适合「企业中后台型」组件库。** Element Plus 默认「老干部风」、Ant Design Vue 偏「严谨商务」，改造成本高且容易打架。
3. **推荐方向：无头（headless）方案 + 自己写样式**，具体首选 **Reka UI**（原 Radix Vue）+ 少量自研组件。理由：这个项目的界面**不是中后台**（不是表格+表单密集），而是"投料 → 可视化 → 对话"三段式，自带强风格诉求。用完整组件库等于买了 80% 不需要的东西，再花力气覆盖它的样式。
4. **如果不想自己写全部样式**：备选 **Naive UI**（主题变量系统最灵活，零依赖 TS API 改色）+ **Arco Design Vue**（有风格配置平台，可可视化调主题）。两者底子比 Element Plus 中性。
5. **不推荐 Tailwind 作为主方案**（虽 shadcn-vue 生态最好）：HJ 未用过，且它会把"改样式"变成"学一套新 DSL"，违反「一个项目只学一样新东西」（`DEV_STANDARD.md` 原则 2）。**本项目的新东西额度应该留给"人格建模"**，不该花在 CSS 工具链上。

## 一、找风格的网站（按用途分类）

> **怎么用**：不要漫无目的地刷。带着一个具体问题去（"投料页的进度该怎么显示"），比"找找感觉"效率高十倍。

### 1.1 真实产品截图库（最有参考价值）

这类站给的是**已上线产品**的真实界面，不是概念稿。做"这个交互别人怎么解"的对照研究最好用。

| 站 | 适合什么 | 免费程度 | URL |
|---|---|---|---|
| **Mobbin** | 真实 App / Web 的完整用户流程（onboarding、checkout、settings）。搜"投料流程"能看到几十个产品怎么做的 | 免费档限少量 App；Pro 约 $2.5/周（年付） | `mobbin.com` |
| **Refero** | 十万+ 网页与 iOS 截图，**人工按组件打标**。搜「empty state」「pricing toggle」能精准命中 | 有免费档 | `refero.design` |
| **ScreensDesign**（原 Design Vault） | iOS 转化流程（onboarding、付费墙）。**每个决策有文字拆解**，这类"讲为什么"的资源很少 | 免费为主 | `screensdesign.com` |
| **Page Flows** | 用户流程录像（不是静态图） | 未验证 | `pageflows.com` |

> 📌 **对 persona-forge 最有用的是 Refero** —— 它的组件级打标能直接回答"对话气泡该长什么样""进度条该怎么显示"这类具体问题。

| **Recent**（原 Godly） | **缩略图带动效预览**，不用点进去就能看动效。策展比 Awwwards 紧 | 免费 | `recent.design` |

| **Httpster** | 极简、字体驱动。**"高级但安静"这个方向的首选参考** | 免费 | `httpster.net` |
| **Land-book** | 落地页，策展严格 | 免费 | `land-book.com` |

| 站 | 用途 | 费用 | URL |
|---|---|---|---|
| **Dribbble** | 视觉冲击型单图。**有颜色筛选**，能搜"某个配色下的设计" | 免费（Pro $8/月） | `dribbble.com` |

### 1.4 配色工具（这个项目最该用的）

「樱桃粉 + 珍珠白 + 淡金」需要落成具体的色值系统，这几件工具能直接产出。

| 工具 | 用途 | 费用 | URL |
|---|---|---|---|
| **Coolors** | 空格键生成配色，可锁定喜欢的颜色继续生成 | 免费（Pro $3/月） | `coolors.co` |
| **Color Hunt** | 社区投票的热门配色，看趋势 | 免费 | `colorhunt.co` |

| **Radix Colors** | 每个色阶 12 档（含暗色模式、对比度合规校验）。**工程化程度最高** | 免费 | `radix-ui.com/colors` |
| **UI Colors**（Tailwind 出品） | 整套色阶可直接复制为 CSS 变量 | 免费 | `uicolors.app` |

> 💡 **建议的工作流**：Coolors 或 Color Hunt 找到感觉 → Realtime Colors 看套在页面上的效果 → Radix Colors 落成 12 档色阶变量。**最后一步很重要**：12 档色阶能让你在"樱桃粉"这一个色相下，拿到从浅底到深字的全部层级，不用每次手动调明度。

## 二、Vue3 组件库选型对比

**评分场景假设**（来自 `SPEC.md` §五 功能清单）：

| 场景 | 需要的组件 |
|---|---|
| 投料页 | 文本域、文件上传、步骤条/进度、卡片 |
| 档案页/可视化 | 雷达图、折线图（**图表库另选**，见 §2.3）、标签、折叠面板 |
| 对话页 | 气泡列表、输入框、流式打字机效果、滚动容器 |
| 全局 | Toast、Modal、Tooltip、主题切换 |

> ⚠️ **关键观察**：这个清单里**几乎没有表格、复杂表单、树形控件** —— 而那正是 Element Plus / Ant Design Vue 最强的部分。**买它 80% 的能力，用不到 20%。**

### 2.1 候选对比

| 维度 | **Reka UI**（原 Radix Vue） | **Naive UI** | **Arco Design Vue** | **Element Plus** | **PrimeVue** |
|---|---|---|---|---|---|
| 官网 | `reka-ui.com` | `naiveui.com` | `arco.design` | `element-plus.org` | `primevue.org` |
| Vue3 支持 | ✅ 原生（Vue 3 专用） | ✅ 原生 | ✅ 原生 | ✅ 原生 | ✅ 原生 |
| 类型 | **无头**（无样式） | 完整组件库 | 完整组件库 | 完整组件库 | 完整组件库 + 无头模式 |
| 主题定制 | **无限**（样式全归你） | TS API 主题变量，无需 Sass | 设计令牌 + 风格配置平台 | SCSS 变量覆盖 | Design Token + Unstyled 模式 |
| 视觉底子 | **无（中性）** | 现代通透、偏暗黑极客 | 灵动现代，字节风 | **传统中后台，"老干部风"** | 国际化，模板多 |
| 组件完整度 | ⚠️ 只有基础原语（需自研组合） | 高 | 高 | **极高** | 极高 |
| 体量 | **极小**（按需引入） | 中（Tree-shaking 良好） | 中 | 中 | 中偏大 |
| TS 体验 | 优秀 | **顶级** | 良好 | 良好 | 良好 |
| 已知坑 | 需自己写全部样式（**工作量在你这**） | 部分冷门组件文档略糙；社区小于 Element | 中文文档为主，高级功能学习成本略高 | 视觉改造困难；与 Vue2 版 `Element` 易混淆 | 中文文档一般 |
| **是否推荐** | ✅ **首选** | ✅ **备选首选** | 🟡 可用 | ❌ 不推荐 | 🟡 可用 |

> ⚠️ **`Element` 与 `Element Plus` 是两个独立项目** —— 前者只维护 Vue2，新项目必须用后者。老资料常混用这两个名字。

### 2.2 为什么不推荐 Element Plus / Ant Design Vue

不是因为它们不好，而是**视觉改造成本**：

| 问题 | 说明 |
|---|---|
| **默认视觉强** | 它们的设计语言（间距、圆角、阴影、灰阶、动效曲线）是成套的。你要改的不只是主色，还有整套"气质" |
| **改主色 ≠ 改风格** | 把主色改成樱桃粉，得到的不是"水晶花瓣质感"，而是"粉色的企业中后台" |
| **组件细节多** | 一个 Button 有 5 种状态 × 4 种尺寸 × 多个变体，每个都可能带默认阴影/渐变，要逐个覆盖 |

> 📌 **判断方法**：如果这个项目的界面**看起来像后台管理系统**，那成功概率就很低。persona-forge 是"陪伴型工具"，视觉上应该更接近**笔记应用 / 音乐播放器 / 日记应用**，而不是 ERP。

### 2.3 图表库另选（不跟组件库绑定）

`SPEC.md` P1 要「雷达图 / 特质分布 / 变化曲线」。主流选择：

| 库 | 体积 | 适合 | URL |
|---|---|---|---|
| **Chart.js** | 小 | 常规图表，上手快 | `chartjs.org` |
| **ECharts** | 中大 | 功能最全，中文文档好 | `echarts.apache.org` |
| **Unovis** | 小 | Vue 原生友好，组件化 | `unovis.dev` |
| **D3** | 大 | 完全自定义（学习曲线陡） | `d3js.org` |

> 💡 **对这个项目**：先用 **Chart.js**（雷达图开箱即用，体积小）。如果后续要做"人格变化曲线"这类定制可视化，再考虑 D3 —— 但那属于「学新东西」，要单独评估（`DEV_STANDARD.md` 原则 2）。

## 三、推荐方案与第一步

### 3.1 推荐：Reka UI + 自研样式

**选它的理由**（按权重）：

| 理由 | 说明 |
|---|---|
| **风格不被绑架** | 无头 = 没有默认视觉，樱桃粉+珍珠白+淡金从零建立，不打架 |
| **符合"单文件 ≤200 行"** | 组件小、职责单一，天然容易保持精简 |
| **符合"一个项目只学一样新东西"** | Reka UI 本身是 Vue3 的组合式 API 原语，**不算新技术栈**；它的心智负担主要在无障碍（a11y）细节，而这部分可以先用基础组件 |
| **体量小** | 纯静态项目，体积敏感 |
| **配套生态好** | shadcn-vue 的很多组件基于它，遇到问题有参考 |

**代价（必须承认）**：

- ⚠️ **所有样式自己写** —— 这是真工作量。Modal、Select、Toast 这类组件要处理焦点管理、键盘导航、滚动锁定等细节，Reka UI 帮你处理了**行为**，但样式得自己来
- ⚠️ **没有"拿来就用"的成品感** —— 前期会比直接用完整库慢

> 🔴 **风险预警**：这条路的最大风险是**样式工作量失控**。建议设定约束：
> **Phase 1 首批页面（投料页 + 对话页）只用最基础的组件**，模态框、下拉选择这些能用原生 `<dialog>` / `<select>` 就先别自己封装。
> 一旦发现"为了做 UI 花的时间超过做功能"，立刻切 Naive UI 兜底。

### 3.2 备选：Naive UI

如果判断"自己写样式工作量太大"，用 Naive UI：

| 优势 | 说明 |
|---|---|
| **主题系统最灵活** | TS API 定义主题变量，**零 Sass/Less 依赖**，只需提供主色就能生成完整调色板 |
| **自带实时主题编辑器** | 官方文档站上有，可以边调边看 |
| **底子中性** | 现代通透风格，比 Element Plus 好改 |
| **TS 体验顶级** | 与项目的 TS 栈契合 |

**代价**：组件默认样式仍有自己的"味道"，需要覆盖一部分；社区规模小于 Element Plus。

### 3.3 第一步该做什么（不用写代码）

> 📌 **建议的顺序：先定视觉，再选库。**

1. **去 Refero / Collect UI 搜「chat interface」「progress steps」**，截图存 10-15 张参考（针对性，不要泛泛地刷）
2. **用 Coolors 定出樱桃粉 + 珍珠白 + 淡金的具体色值**，再到 Radix Colors 落成 12 档色阶变量（浅底 → 深字整套）
3. **做一页静态 HTML 原型**（不用 Vue，直接 HTML+CSS）—— 就做**投料页**，把配色、圆角、阴影、字体全定下来
4. **拿原型去试**：把同一份 CSS 分别套到 Reka UI 和 Naive UI 上，**哪个体感更好一眼就能看出来**
5. 定完再写 ADR

> 💡 **第 3 步是关键**：一页静态原型能避免"选完库才发现风格做不出来"这个最常见的返工。而且它**不需要新依赖、不需要学新东西、反馈即时**（符合 `DEV_STANDARD.md` 原则 6）。

## 四、明确不做的事

| 不做 | 为什么 |
|---|---|
| ❌ 不引入完整企业级组件库（Element Plus / Ant Design Vue） | 视觉改造成本 > 收益，用不到 80% 的能力 |
| ❌ 不用 Tailwind（除非先单独评估） | 会占用"一个新东西"的额度，本项目的额度应留给人格建模 |
| ❌ 不同时试多个库 | 那是横向对比调研，不是开发；选定一个走到底 |
| ❌ 不追求"组件齐全" | 这个项目的界面简单，缺什么补什么 |
| ❌ 不在选库阶段引入动画库 | 水晶质感靠 CSS（`backdrop-filter` / `box-shadow` / 渐变）就能做，不必上 Framer Motion 类重库 |
