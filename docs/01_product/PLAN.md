# 交付计划与里程碑

> **什么时候读这份文档**：动手做某个 Phase 之前；或判断"某个功能该放进哪一阶段"时。
>
> **它不是**：功能清单（那是 `SPEC.md`）也不是当前进度（那是 `../00_meta/STATUS.md`）—— 它只规定**顺序、完成标准和风险**。
>
> **它能回答**：Phase 1 要做到什么程度才算完？这个项目最可能怎么死？每个阶段明确不做什么？

> 状态：v1.2 · 最后更新 2026-09-18（v1.2 = Phase 2 范围确认；v1.1 反映 D007 转向）
> 上游文档：[SPEC.md](./SPEC.md) · [PRODUCT.md](./PRODUCT.md) · [STATUS.md](../00_meta/STATUS.md)
> 原则：**每个阶段产出一个能跑起来的垂直切片**，不是横向铺一层功能。

---

## 零 · 一句话

不是「先做完前端再做后端再做语音」，而是「先让一个最简单的人格跑通一次完整对话」，然后逐层加厚。

## 一 · 阶段总览

| 阶段 | 目标 | 产出物 | 完成标准 |
|---|---|---|---|
| **Phase 0** | 验证「LLM 能否从真实材料里提取出可用的人格剖面」 | 验证记录 + Prompt 结论 | ✅ **已完成两轮** —— 见 [STATUS §二](../00_meta/STATUS.md) |
| **Phase 1** | 脚手架 + 单人格静态对话 + **执行侧干预验证** | 可运行的网页 | 能选一个人格、发消息、收到回复，刷新后对话还在；**且施压场景下不退回默认 AI 模式** |
| **Phase 2** | 投料模块（**仅虚拟角色**） | 投料页面 + 提取流程 + `PersonaProfile` 落地 | **A 类材料走通一次** → 生成人格剖面 → 可直接用这个剖面开聊；**六维不低于手写素材水平** |
| **Phase 2.5** | 真人素材投料（**新增**） | 单独同意流程 + 敏感信息处置 | 真人档案可投料，且**功能上不提供**导出/分享入口 |
| **Phase 3** | 记忆与演化 | 记忆卡片 + 演化面板 | 对话里提到的信息被记住，并在下一轮对话里被用上；演化面板能看到变化 |
| **Phase 4** | 多人格 + 数据管理 | 人格列表页 | 创建/切换/删除人格，数据可导出 |
| **Phase 5** | 语音（可选） | TTS 接入 | 收到回复时能听到声音 |

**Phase 5 是明确的可选阶段**，前 4 个阶段做完项目就已经成立。语音不要提前做。

> Phase 2 增加 0 号任务（`PersonaProfile` 落地）与第 4 条验收标准（六维质量下限）；
> 交付形态定为 Vue Router + 两个页面。**逐项理由见 §二 Phase 2 的确认块。**

> 📌 **v1.1 变更**：Phase 0 已完成，Phase 1 增加「执行侧干预」验证目标，Phase 2 的投料模块增加「层级清洗」。

### Phase 1 · 脚手架 + 单人格静态对话 + 执行侧干预

**垂直切片**：从「没东西」到「能聊天」，中间不接任何花哨功能。

| 项 | 内容 |
|---|---|
| 内容 | 项目脚手架（Vue3 + TS + Vite）· 一个页面 · 一个人格（硬编码在文件里）· 对接 LLM · 对话存储 · **执行侧干预层** |
| 产出 | `npm run dev` 能跑起来；发消息有回复；刷新不丢 |
| 完成标准 | 连续聊 10 轮不崩；关掉浏览器再打开，历史还在；`npm run build` 通过；**施压场景测试不退回默认 AI 模式** |
| 明确不做 | 不做投料、不做多角色、不做记忆、不做语音、不做动效 |
| 预计规模 | 5–8 个文件，每个文件 ≤ 200 行 |

**这一阶段的两个隐藏重点**：

1. **把「模型接入层」写干净。** 它要同时支持本地 Ollama 和云端 OpenAI 兼容 API，用一个配置文件切换。
   这一层写好了后面所有阶段都受益；写烂了后面处处是坑。
   > ✅ **已提前落地**（2026-09-18）：`exp/e5_runner.py` 已验证三后端配置驱动，
   > 换模型改 `.env` 三行、**零代码改动**。选型见 [`D011`](../02_decisions/D011-主基座与开销纪律.md)。脚手架可沿用这套结构。
2. **把「执行侧干预」验证做掉。** 这是 D007 定的 P0 方向，也是项目**唯一未验证的核心假设**：
   在生成时加自检 / 注入反面示例，能否让角色面对用户施压时**不退回**「顺从用户显式要求」的默认模式。
   > ✅ **已验证**（2026-09-18，E5 三批数据）：**配置 B（三明治 + 重注入）最优，23/30**。
   > **成对示例有害（−6），不上。** 结论见 [`E5-执行侧干预.md`](../04_lab/phase1/E5-执行侧干预.md) §5.5。

> ⚠️ **Phase 1 的这两个前置已全部完成**（2026-09-18）。
> **下一步是搭脚手架。** 见 [STATUS §四 下一步](../00_meta/STATUS.md)。

### Phase 2 · 投料模块

> ✅ **范围已于 2026-09-18 与 HJ 逐项确认**（5 项待确认项全部拍板）。
> 下表已按确认结果更新 —— **这是 Phase 2 的唯一有效范围定义**。

| 项 | 内容 |
|---|---|
| 内容 | 投料页面（**纯文本 / 文档上传 / 手工粘贴**，见下方 ⚠️）· **层级清洗（标出 + 用户勾选）** · 层级检测引导 · 提取流程（调用 LLM）· 两种模式（一键黑盒 / 手动微调）· 素材来源标注 · 情境映射表 · 反例训练 |
| 0 号任务 | **`PersonaProfile` / `FrozenLayer` 落地为 `.ts` 类型 + 存储层**（`persona-schema.md` §四 目前仍是 `draft`，从未被代码实现）。**只实现 `frozen` 层**，`evolving` 留 Phase 3 |
| 产出 | 能从一个**虚拟角色**的剧情文本里生成人格剖面，并立刻用它开聊 |
| 完成标准 | ① A 类材料（剧情台词）走通一次 ② 提取出的剖面四段结构完整 ③ 用户能手动改任一字段并生效 ④ **提取剖面跑一次六维评分，不低于 Phase 0 手写素材的水平** |
| 交付形态 | **Vue Router + 两个页面**：对话页（现有 `App.vue`）/ 投料页（新增 `/feed`） |
| 依赖 | ✅ Phase 0 的 Prompt 结论（已满足） |
| 规模红线 | 单文件 ≤ 200 行；`App.vue` 已 115 行，**拆分是硬要求** |

> 🔴 **投料对象限定为虚拟角色（动漫 / 游戏 / 小说 / 原创）。**
> **真人素材（朋友 / 亲人的聊天记录）不在 Phase 2 范围内**，留 Phase 2.5。
> 理由：真人场景会触发个保法「敏感个人信息 + 单独同意」（`../05_research/合规专项调研.md` R4/R5/R6），
> 且 `SPEC.md` §十 第 12 条要求真实人物**不渲染**导出/分享按钮 —— 都是功能新增量，混做会让范围翻倍。

**这一阶段是全项目价值最集中的地方** —— 投料体验好不好，直接决定「像不像」。

> 📌 **按 D007 调整投入顺序**：**层级清洗（P1）优先于层级检测（P2）**。
> 「清洗」是把混进素材里的**他人已蒸馏好的分析结论**剔出去（否则提取器会抄答案）；
> 「检测」是判断素材有没有第二层。前者是新需求，后者降级保留。
>
> 📌 **清洗采用「标出 + 用户勾选」而非自动剔除**（2026-09-18 确认）——
> 避免误删真素材，且符合「手动微调是核心体验」的定位。
> 纯自动留到有真实数据后再评估（与 `persona-schema.md` §2.1「没有真实数据不凭空设计」同一条纪律）。

> ⚠️ **`SPEC.md` §六 的「结构化对话（JSON/CSV）」来源暂缓** ——
> 它需要写解析器且典型层级为单层，收益低于纯文本与文档两条路径。
> 等 A 类材料跑通后再评估，**不占 Phase 2 主力资源**。

### Phase 3 · 记忆与演化

| 项 | 内容 |
|---|---|
| 内容 | 记忆卡片（结构化 + 关键词触发）· 记忆注入对话 · 演化面板（4 个 panel + evolutionLog）· 快照与回滚 |
| 产出 | 聊得越多越像；能看见它「变了什么」；能退回上一个版本 |
| 完成标准 | 三件事必须成立：① 对话里说的信息下一轮被用上 ② 演化面板能看到至少 2 次有效变化 ③ 能回滚到任意一个历史快照 |
| 难点 | 冻结层 / 演化层的边界划分（见 SPEC §四）—— 这块规则定不好会出现「人设跑偏」 |

**这一阶段完成后，项目最核心的差异化就成立了**：不只是「它记得」，而是「你看见它记得，而且你能管它怎么变」。

### Phase 5 · 语音（可选，最后做）

| 项 | 内容 |
|---|---|
| 预研结论 | 实时全双工语音（200–400ms）需要本地跑端到端模型，硬件门槛高；**v1 只做「文字对话 + TTS 朗读回复」** |
| 候选 | GPT-SoVITS（少样本、中文社区成熟、6GB 显存）· IndexTTS-2（音色-情感解耦）· CosyVoice 2（流式 150ms） |
| 完成标准 | 收到回复后能点播放，听到与目标角色接近的音色 |
| 前置条件 | Phase 1–4 全部完成且稳定运行两周以上 |

**为什么放最后**：语音是最容易让人兴奋、也最容易把项目拖垮的部分。它会牵出模型下载、显存、Python 环境、音频格式一堆问题 —— 在核心体验还没被验证之前碰它，就是自杀。

## 三 · 节奏与检查点

| 规则 | 说明 |
|---|---|
| 时间盒 | 每个 Phase 设时间盒，到点就必须出一个「能演示」的版本，宁可砍功能 |
| 每两周演示 | 打开浏览器给朋友看一遍。演示不出来 = 阶段没完成 |
| 每周四问 | ① 这周代码行数变化多少 ② 有没有超过 200 行的文件 ③ 还能说清每个文件在干什么吗 ④ 这周的产出能不能跑 |
| 三条红线 | 单文件 > 300 行 · 连续两周没有可运行的产出 · 说不清某个文件的作用 → 任一触发，停下来整理，不加新功能 |

（机制细节见 [DEV_STANDARD.md](../06_ops/DEV_STANDARD.md) §四）

## 四 · 风险与规避（Pre-mortem）

假设一年后这个项目死了，最可能的原因是什么？按可能性排序：

| # | 死亡原因 | 早期信号 | 规避方式 |
|---|---|---|---|
| 1 | **需求蔓延** —— 想加语音、加桌面端、加 App、加插件 | 开始讨论「顺便也支持一下…」 | Non-Goals 写进 SPEC 并严格执行；新想法一律记进「待办池塘」，不进当前 Phase |
| 2 | **Prompt/效果调优黑洞** —— 不满足于「像」，反复调，没有终止条件 | 连续两周都在改 Prompt，代码没动 | Phase 0 已用硬阈值 + 半天时间盒跑完；**Phase 1 沿用同一规则**：效果「够用」即冻结，进入下一阶段 |
| 3 | **被新技术吸引** —— 想上向量库、上微调、上 Agent 框架 | 开始读微调教程 | **一个项目只学一样新东西**；本项目要学的是「人格结构化 + 演化可视化」，别的都是噪声 |
| 4 | **上下文爆炸** —— 和老对话聊太久，AI 开始胡改代码 | AI 改的文件不是你要的那个 | 每个 Phase 开新对话；交接读 PRODUCT.md；大改前先 commit |
| 5 | **硬件/环境卡死** —— 想本地跑模型，跑不动 | 反复折腾显卡和 Python 环境 | 本项目默认走云端 API，本地模型是「可选增强」不是前提 |
| 6 | **隐私顾虑导致停摆** —— 担心私人聊天数据外泄 | 不敢投真实材料 | 数据全部存本地（IndexedDB/本地文件）；投料前有脱敏提醒；只发必要上下文给 API |

**最高优先级的一条**：第 1 条。这个项目的功能列表已经足够克制，最大的敌人是你自己在 Phase 2 之后产生的新想法。
