## 一、产品定位

**persona-forge（人格工坊）**

> 喂给它一个人说过的话，它就能像那个人一样和你聊天 ——
> 而且你能看见它记住了什么、变成了什么样。

**一句话**：一个既好用、又能让你看见它内心在发生什么的 AI 伙伴。

### 1.1 定位：B + C（已决策 2026-09-16）

| 层 | 内容 | 阶段 |
|---|---|---|
| **B（当前主体）** | 单人格的投料 → 对话 → 演化闭环，跑通完整链路 | **Phase 1–3** |
| **C（后续计划）** | 多人格编排 / 更复杂的演化结构 | **Phase 4 之后** |

> 📌 **先做 B 的理由**：C 是"B 跑通之后自然长出来的东西"，不是独立功能。
> HJ 明确要看 **B 做完的实际效果** 再决定 C 的形态 —— 避免现在就为想象中的需求搭架子。

### 1.2 投料来源：用户自有数据

本项目**只处理用户自己提供的素材**（自己的聊天记录 / 自己收集的剧情台词 / 自己整理的文档）。
**不提供、不内置任何现成角色素材包。**

> 这既是产品选择，也是合规底线 —— 见 §十 第 11 条与 §十二。

### 1.3 ⚠️ 公开链接 ≠ 公开投料（必须分清）

HJ 决策「上线公开链接」，但**这不等于明志开放投料**。两者是不同的事：

| | ✅ 公开链接（做） | ❌ 公开投料（不做，v1） |
|---|---|---|
| 访客能做什么 | **体验已发布的人格**、看演化可视化 | 上传自己的素材、建自己的人格 |
| 数据流向 | 只读（对话记录留在访客浏览器本地） | 要上传到服务器 |
| 需要什么 | 静态托管 + 一个只读接口 | 账号体系、存储配额、上传清洗、审核 |
| 合规面 | 拟人化标识 + 内容安全 | **再加：个人信息处理、素材版权、未成年人保护** |

> 🔴 **v1 的范围是「公开体验 demo」，不是「公开人格工坊 SaaS」。**
>
> - P2 公开访客**用的是 HJ 自己投料发布的人格**，不是自己的
> - 「访客自己投料」属于 **v2+**，且一旦要做，§12.4 清单会显著变长
> - 这也是 §二「v1 不考虑公开注册、多租户、账号体系」的原因

> ⚠️ **本节是为了消除一个潜在的自相矛盾**：§二 新增了「公开访客」，
> 但 §1.2 说「只处理用户自有数据」—— 若不写清，会看起来互相打架。
> **实际是：投料的是 HJ，访客只是使用。**

## 三、核心任务（JTBD）

| 任务 | 说明 | 权重 |
|---|---|---|
| **陪伴对话** | 日常闲聊、吐槽、分享、询问 —— 像真实的人一样 | **地基** |
| **人格复刻** | 从素材（聊天记录 / 剧情台词）提取说话风格与性格 | 核心 |
| **演化观察** | 看着它记住更多、变得更熟悉、人格随时间变化 | 差异化 |
| **技术验证** | 亲手做一遍长期记忆 + 人格建模 | 学习目标 |

### ⭐ 一个关键洞察（来自需求澄清）

用户的两个场景 —— **记录亲人** 和 **模仿二次元角色** —— 本质是**同一件事**：

> **喂给它"这个人说过的话"，让它学会"这个人怎么说话"。**

素材来源不同（聊天记录 / 剧情台词），但**处理管道是同一套**。

**所以产品只有一个核心抽象：人格档案（Persona Profile）。**

## 四、核心架构：人格剖面

**这是整个项目的技术锚点。**

```
┌─────────────────────────────────────────┐
│  冻结层 · Frozen                         │
│  核心性格 / 价值观 / 说话基调 / 口头禅     │
│  → 用户定义或投料提取，AI 不可修改         │
├─────────────────────────────────────────┤
│  演化层 · Evolving                       │
│  对用户的认知 / 关系状态 / 共同记忆        │
│  → 自动累积，但必须可见、可回滚            │
└─────────────────────────────────────────┘
```

### 冻结层包含什么

| 字段 | 示例 |
|---|---|
| 性格关键词 | 温和、话少、爱开玩笑 |
| 价值观倾向 | 重视家人、不喜欢炫耀 |
| 情绪基调 | 偏平静，偶尔毒舌 |
| 说话风格 | 句子短、爱用「哈哈」结尾、几乎不用感叹号 |
| 口头禅 / 高频词 | 「行吧」「你说了算」 |
| 称呼方式 | 叫对方「伙计」 |

### ⭐ 冻结层的两个子类（Phase 0 实测新增）

**实测发现：人格特征分两类，prompt 里的写法完全相反。**

| 子类 | 定义 | prompt 写法 | 例子 |
|---|---|---|---|
| **表现型** | 要**演出来**的特征 | 正向描述 | 句子短；用破折号；爱用比喻；情绪冷时反而句子更短 |
| **约束型** | 要**禁止说出来**的特征 | **反向禁令** | 禁止直接陈述自己的情感状态；禁止解释自己为什么冷；禁止长篇安慰 |

> 🔴 **为什么必须分开**：AI 味的根因是**模型天然倾向于把内心戏讲出来**。
>
> Phase 0 实测中，扮演代理自己诊断出：
> > 我把"核心矛盾"写成了**需要被表达的特征**（"必须体现"），
> > 而它应该是**约束条件**——"禁止直接说出情感状态，只能通过物件/动作/玩笑漏出"。
> > **写成"要体现"，就会演成自我剖析。**
>
> 这一条把扮演分数从 21/30 卡住的下限直接暴露了：内在矛盾 3/5、出戏情况 2/5。

**实现要求**：人格档案结构中，约束型特征必须**单独成组**，并在拼装 System Prompt 时放入"绝对禁止"区块。

### ⭐ 约束条件必须独立成文件（竞品实测强化）

> 来源：[`../05_research/竞品-elysia.skill.md`](../05_research/竞品-elysia.skill.md) §4.3
>
> 竞品把这一整类写成独立的 `conflicts.md`，7 类 OOC 风险：
> 核心身份 / 时间线 / 性格平衡 / 情感表达 / 融合战士 / 语言风格 / **新旧设定**。
>
> 它用的句式不是"她是什么"，而是"**写成什么样就错了**"。例：
> > **OOC 风险**：若将爱莉描述为「第十三位律者」，则违背官方核心设定。
>
> **架构决定**：不把约束条件塞进 Prompt 文本，而是**独立成一个文件 + 分类**。
> 理由：约束是**反向资产**，会随实测不断追加（每发现一次 OOC 就加一条），
> 塞在 Prompt 里会越来越乱且容易被挤掉。独立成文件才好维护、好 diff。
>
> **「新旧设定」这一类值得单独留意**：素材本身自相矛盾时（早期版本说 A、后期版本说 B），
> 需要一条明确的**时序仲裁规则** —— 竞品的答案是以最新版本为准。我们迟早会撞上这个问题。

### ⭐ 分析必须翻译成可执行条件（竞品实测的最大教训）

> 来源：[`../05_research/竞品-elysia.skill.md`](../05_research/竞品-elysia.skill.md) §3.2
>
> 竞品的 `personality.md` 把爱莉希雅的三大内在矛盾分析得**非常漂亮**
> （理想 vs 现实 / 掌控 vs 放任 / 神性 vs 人性），每个矛盾还配了"统一点"。
> **但四轮扮演实测里，反差层次只拿到 2.75/30 —— 最低分。**
>
> **根因是分析与执行之间的断裂。** 它写的是：
> > 「用诗意语言包裹沉重现实」
>
> 这是**影评**。可执行版本应该是：
> > 「沉重话题时：句长从 12-15 字拉到 20-28 字；语气词率从 70% 降到 30%；
> > 保留 ♪ 但在句中出现而非结尾；先接住情绪再引向希望。」
>
> **硬性要求**：档案里每一条关于"怎么说"的描述，都必须是
> **「可被第三人照着执行的动作描述」**，禁止出现"有韵律感""旋律感""不短促粗硬"
> 这类**无法验证的形容词**。
>
> 自检方法：把这条描述交给一个没读过素材的人，他能不能照着做？
> 不能 → 这条描述无效，重写。

### 演化层包含什么

| 字段 | 示例 |
|---|---|
| 对用户的认知 | 用户是程序员、最近在忙一个项目 |
| 关系状态 | 关系阶段、亲密度、共同经历 |
| 记忆卡片 | 「用户提到过妹妹叫小雨」（带时间和证据） |
| 演化快照 | 每次对话后的状态记录（用于画曲线和回滚） |

### ⚠️ 关键难点：边界划分

**"对某句话的幽默感"算冻结层还是演化层？**

这个划分没做好，要么角色变成木头（全冻结），要么人设崩塌（全演化）。

**当前初步规则**：
- 冻结层管「**怎么说**」（风格、价值观、基调）
- 演化层管「**知道什么**」（事实、关系、偏好）

细节待 `docs/03_specs/persona-schema.md` 补充。

## 六、投料模块设计

> ⚠️ **本节已被两轮 Phase 0 实测修正。** 第一轮结论见
> `../_archive/phase0/Phase0结论报告.md`（**核心发现已被第二轮修正**；已于 2026-09-17 归档，不作为依据），
> 第二轮总纲见 [`../04_lab/phase0/三方对照结论.md`](../04_lab/phase0/三方对照结论.md)。
>
> 🔴 **最重要的一条修正（第二轮）**：**素材侧不是瓶颈。**
> 素材质量对反差层次的**边际收益在第 3 分处归零**（E3 素材量仅 E2 的 25%，分数只涨 1 分）。
> 真正的瓶颈在**「模型执行」侧** —— 见 [`../02_decisions/D007-Phase1转向执行侧.md`](../02_decisions/D007-Phase1转向执行侧.md)。
>
> **本节功能据此重排优先级**：层级清洗 **P1** > 层级检测 **P2**（原 P0，已降级）。

### 关键概念：材料层级（Phase 0 新增）

| 层级 | 形态 | 能提取什么 | 提取不到什么 |
|---|---|---|---|
| **单层** | 纯对话、纯台词、聊天记录 | 语言风格、行为模式、表层性格 | ❌ 内在反差、行为矛盾、情绪切换规律、说话节奏 |
| **双层** | 小说原文、剧本、带场景描写的对话 | 全 10 类特征 | — |

**双层 = 除了「她说了什么」，还有「她说话时的动作/表情/环境/他人视角」。**

> ⚠️ **理论修正（E2 组提出）**：决定提取深度的是**「第二层的视角」**，不只是"层数"。
> 本项目的实测素材，其第二层是**他人转述**（"别人说她怎样"），所以能提取矛盾与机制，
> **但拿不到行为细节**。现行表述应为：
> **提取深度 ≤ 素材提供的「视角丰富度」**。

> 🟡 **为什么这条仍值得保留**：它解释的是「**下限**」而非「上限」。
> E1（14 分）证明素材差会显著拉低下限 → 素材侧不能放弃，但**不该是主攻方向**。

### 支持的来源

| 类型 | 说明 | 解析方式 | 典型层级 |
|---|---|---|---|
| **A 纯文本** | 微信/QQ 导出的聊天记录、txt、md | 直接读 | ⚠️ 通常单层 |
| **B 结构化** | JSON、CSV | 需写解析器 | ⚠️ 通常单层 |
| **C 文档** | PDF、Word、**小说原文、剧本** | pdf.js / mammoth.js | ✅ 通常双层（**推荐**） |
| **手工粘贴** | 直接粘贴文本 | 直接读 | 视内容而定 |

### 投料量要求（第一轮实测得出）

实测数据：400 字 ≈4.5/10；900 字（情绪同质）≈5.5/10；**1800 字（含冲突+离别）≈8/10**。

> **瓶颈不在字数，在「情绪类型覆盖率」。**
>
> **硬性条件**：不少于 3 个场景，且**必须包含至少 1 个非温柔情绪场景**
> （冲突 / 拒绝 / 发怒 / 离别 / 悲伤任选其一）。
>
> **建议话术**（不要对用户说"请准备 2000 字"）：
> > 「请提供至少 3 段这个人说的话，其中至少 1 段是她在情绪极端时（生气 / 难过 / 告别 / 拒绝）的记录。」

> 📐 **完整数据与论证**：`../_archive/phase0/测试结果-投料量对照.md`（唯一做过此实验的文件；已于 2026-09-17 归档，不作为依据）。本节上方的实测数据即为当前有效口径。

### 层级清洗（P1 — 优先级高于层级检测）

**问题**：实测发现，外部素材里**混着原作者已经蒸馏好的分析结论**。
E1 组的素材 `interaction.md` 第 447-543 行（占全文 **28%**）不是原始台词，
而是原作者用模型跑出来的「8 大句子骨架 / 语气温度谱 / 情绪映射表 / 语言禁忌」。

> **后果**：提取器会「抄答案」而不是「做提取」，测出来的能力是假的。

**产品行为**：投料时识别并**剔除**这类"已成结论"的段落，或在 UI 上标出「这段是作者的总结，不是原始素材」。

> 🔬 **配套的校验手段（P3）**：**抽样回查原始数据**。
> E1 组撞出的硬证据 —— 原作者声称「『哟』是常用语气词」，实际台词库出现 **0 次**；
> 声称首要意象是「花」，实际最高频是「爱」（**40 次 vs 28 次**）。
> **整理者写好的结论，可能与其声称依据的原始素材不符。**

### 材料层级检测（P2 — 原 P0，已降级）

> ⚠️ **降级理由（D007）**：素材侧边际收益在第 3 分处归零。此功能保留作**下限兜底**，不占 Phase 1/2 的主力资源。

用户上传后自动检测**是否包含语言之外的第二层信息**（引号外的叙述、动作动词、表情/环境描写）：

| 检测结果 | 产品行为 |
|---|---|
| 检测到两层 | 提示"可以提取深层人格特征" |
| 只有一层 | 提示"当前材料只能提取语言风格和表达习惯" + **引导补充** |

**引导话术**：
> 「越接近小说或剧本的文本越好 —— 因为『她嘴上说 X，但身体做了 Y』这类信息，
> 是我们识别深层人格的关键。」

**可选交互**：纯台词提取后主动问用户"她说话时通常是什么表情？有没有动作和环境的描写？"
—— 把缺失的第二层信息**向用户要回来**，而不是靠模型猜。

### 素材来源标注（竞品实测新增）

> 来源：[`../05_research/竞品-elysia.skill.md`](../05_research/竞品-elysia.skill.md) §4.1
>
> 逐条标注素材可信度，三档：
>
> | 档位 | 含义 | 例 |
> |---|---|---|
> | `verbatim` | 原文逐字（有出处） | 官方台词、聊天记录原句 |
> | `artifact` | 二手整理 / 考据推断 | 「她应该会…」这类转述 |
> | `impression` | 主观印象 | 「我觉得她是个温柔的人」 |
>
> **为什么重要**：`artifact` 档是编造的主要入口。把"素材明示 / 素材暗示 / 我的外推"分开标，
> 用户一眼能看出哪些结论可靠、哪些是 AI 在猜。
>
> ⚠️ **必做**：统计要**覆盖全部素材文件**、**去重**、并把可信度比例做成**门禁**
> （低于阈值拒绝进入对话）。竞品在这里做了标记却没做统计完整性 —— 它的
> `impression` 档定义了从未使用、只统计 1 个文件，导致"95%"是个造假数字。

### 情境映射表（竞品实测新增）

> 来源：[`../05_research/竞品-elysia.skill.md`](../05_research/竞品-elysia.skill.md) §7
>
> 光有"性格描述"不够，要建立 **「情境 → 反应」映射**：把常见互动场景穷举成表，
> 每格填典型反应 + 原文证据。
>
> 竞品列了 10 类：被夸奖 / 被质疑 / 被调戏 / 对方示弱 / 对方求助 / 对方告别 /
> 对方提起沉重话题 / 对方害羞 / 对方惊喜 / 被冷落。
>
> **为什么比"性格描述"强**：性格描述是形容词（不可执行），情境映射是**触发器 → 行为**（可执行）。

### 反例训练（竞品实测新增）

> 来源：[`../05_research/竞品-elysia.skill.md`](../05_research/竞品-elysia.skill.md) §7
>
> 除了"该怎么说"，还要提供**成对反例**：❌ 通用版 → ✅ 角色版。
>
> 例：
> ```
> ❌ 通用版：别难过了，一切都会好起来的。
> ✅ 角色版：哎呀，谁把你欺负成这样啦？过来，我看看。
> ```
>
> **为什么比禁令高效**：禁令（"不要安慰得像客服"）需要模型自己推断该改成什么；
> **对比示例直接给出转换规则**，一次就能学到位。竞品做了 10 组，是我们没有的维度。

## 八、记忆方案

**采用：结构化记忆 + 关键词触发**（不用向量检索）

| 方案 | 为什么不用 |
|---|---|
| ① 全量塞上下文 | 长了就爆 |
| **② 结构化 + 关键词** | ✅ **采用**。性价比最高，可视化天然更好，每环节可理解 |
| ③ 向量检索 RAG | 需要 embedding 模型（本地跑不动）、多一份 API 成本、可视化差 |

**理由详见** `02_decisions/D004-记忆方案.md`

**实现参考**：SillyTavern 的世界书（World Info）机制 —— 关键词触发，
成熟且被验证过。

## 九、可视化面板

| 面板 | 展示内容 | 优先级 |
|---|---|---|
| **记忆面板** | 它现在记得我什么（结构化卡片） | P1 |
| **人格画像** | 性格特质雷达图 | P1 |
| **变化曲线** | 人格随时间的变化，标记变化点 | P1 |
| **内心独白** | 它此刻的情绪 / 想法 | P1 |

### ⭐ 变化曲线的实现基础

每次对话后存一个**人格快照**：

```js
evolutionLog = [
  { time, frozenHash, evolvingSnapshot, triggerSummary },
  ...
]
```

**三个好处**：
1. 变化曲线 = 把这个数组画成折线图
2. 天然支持**回滚**（每一帧都存着）
3. **可以直接算学术界的人格漂移公式**：
   `Drift = (1/T)·Σ‖v_t − v_0‖₂`

### 第 7 条特别说明

**LoRA 微调是最大的范围炸弹**：
- 需要 GPU
- 需要数据清洗管道
- 训练一轮几小时
- 效果还不一定好

**"prompt + 记忆 + 检索"能达到 80% 的效果，且完全不需要 GPU。**

**如果哪天想加微调 —— 那是一个独立项目，不要塞进来。**

### 第 8 条修订说明（分享功能的边界）

原第 8 条写「❌ 公开角色卡分享社区」。**HJ 于 2026-09-16 决策要提供分享/导出功能**，
两者需要划清边界，否则会互相矛盾：

| | ❌ 分享社区（仍然不做） | ✅ 单体分享/导出（做） |
|---|---|---|
| 形态 | 有列表、有搜索、有榜单、可浏览他人作品 | **点对点**：生成一个链接或文件，给出去 |
| 是否有人逛 | 有，是一个内容平台 | 无，没有广场 |
| 内容从哪来 | 别人上传的 | **你自己投料的** |
| 工作量 | 需要后端内容系统、审核、举报、权限 | 一个序列化 + 一个读取接口 |

> **一句话**：我们做「**导出/分享这一个**」，不做「**一个社区**」。
> 没有发现页、没有排行榜、没有"看看别人做了什么"。

### 第 10 条修订说明（合规：从"不谈"到"必须做"）

原第 10 条写「❌ 内容审核 / 合规机制（本阶段不谈）」。

**该条在「上线公开链接」决策后不再成立。** 见 §二 P2 与 §十二。
**新的表述**：内容审核机制不在 **Phase 1–2** 做（那时还没有公开入口），
但**上线公开链接之前必须做**，且必须与上线同批次交付 —— 不能先上线后补。

### 第 11 条：不做逝者复刻

**HJ 于 2026-09-16 明确决策：不做「逝者复刻」。**

| | 说明 |
|---|---|
| **允许** | 虚拟角色（游戏 / 动漫 / 小说人物）、历史公众人物、用户本人 |
| **禁止** | 用已故之人的素材（聊天记录、语音、影像）复刻出可对话的人格 |
| **为什么** | 这一场景的伤害不可逆：家属可能被"复活"的假象反复撕裂，且无法取得当事人同意 |
| **边界模糊时怎么办** | **默认不做。** 若素材指向一个已故的具体个人，投料流程应明确拒绝并说明原因 |

> ⚠️ **注意这不是技术限制，是产品红线。** 技术上完全做得到 —— 正因为做得到，才必须写下来。

### 第 12 条：真实人物的分享边界

**HJ 于 2026-09-16 决策：分享 / 导出功能只对「虚拟角色」开放。**

| 人格类型 | 对话 | 本地保存 | **分享 / 导出** | 公开链接 |
|---|---|---|---|---|
| **虚拟角色**（动漫 / 游戏 / 小说 / 原创） | ✅ | ✅ | ✅ | ✅ |
| **用户本人** | ✅ | ✅ | ✅ | ⚠️ 仅本人可见 |
| **真实人物**（朋友 / 亲人 / 熟人） | ✅ | ✅ | ❌ **不提供** | ❌ **不提供** |
| **逝者** | ❌ 不做（第 11 条） | — | — | — |

> **为什么真实人物不能分享**：素材是他人的聊天记录，**当事人没有同意**。
> 自己私用是私人领域的事；一旦能导出、能生成公开链接，就变成了**对他人人格的未授权复制**。
>
> **实现要求**：这不是靠"用户自觉"，而是**功能上不提供入口** ——
> 真实人物类型的档案，导出/分享按钮**不渲染**（不是灰色禁用，是根本不存在）。
