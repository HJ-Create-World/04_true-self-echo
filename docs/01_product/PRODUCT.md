## 一、项目是什么

**真我回响**

> 喂给它一个人说过的话，它就能像那个人一样和你聊天 ——
> 而且你能看见它记住了什么、变成了什么样。

**一句话定位**：一个既好用、又能让你看见它内心在发生什么的 AI 伙伴。

不是角色扮演工具，不是研究工具，是**透明的陪伴者**。

### 价值主张拆成两半

| 半边 | 说明 | 优先级 |
|---|---|---|
| **好用的陪伴** | 日常闲聊、吐槽、分享、询问 | **地基，Phase 1 必达** |
| **透明的机制** | 能看见它记得什么、人格如何演化 | **差异化** |

⚠️ **顺序不能反**：聊天体验不好，可视化做得再漂亮也没意义。

## 四、核心架构基石：人格档案

**这是整个项目的技术锚点。**

> ⚠️ **字段定义见 `../03_specs/persona-schema.md`。本节只说设计意图，不复述字段。**

```
┌─────────────────────────────────────────┐
│  冻结层 · Frozen                         │
│  核心性格 / 价值观 / 说话基调 / 口头禅     │
│  → 用户定义或投料提取，AI 不可修改         │
├─────────────────────────────────────────┤
│  演化层 · Evolving                       │
│  对用户的认知 / 关系状态 / 共同记忆        │
│  → 自动累积，但必须可见、可回滚            │
└─────────────────────────────────────────┘
```

**它解决了三个问题**：

1. 用户「有时要固定人设，有时要它成长」→ 不是开关，是两层各司其职
2. 学术界说的「人格漂移」→ 漂移只允许发生在演化层，冻结层受保护
3. 演化可视化 → 演化层每次变化都存快照，天然支持曲线绘制和回滚

### ⭐ Phase 0 新增的关键设计约束

**人格特征分两类，prompt 写法相反**：

| 类型 | 写法 | 例 |
|---|---|---|
| **表现型**（要演出来） | 正向描述 | 句子短；用破折号 |
| **约束型**（禁止说出来） | **反向禁令** | 禁止直接陈述情感状态 |

**AI 味的根因是模型倾向于把内心戏讲出来** —— 约束型特征就是用来堵这个口子的。

> 细节见 `../03_specs/persona-schema.md` §3。

## 五、差异化方向：人格的 Git

> ⚠️ **完整论证见 `../05_research/开源生态盘点.md` §6。**

**定位**：把人格档案当代码管理 —— 每次演化产生 snapshot，带 diff、时间线可视化、一键回滚。

**市场验证结论**：

| 判断 | 依据 |
|---|---|
| 产品侧**零竞品** | Character.AI / Replika / 星野 / SillyTavern 全都没有 |
| 学术侧**已有** | `persona_drift` 等已画出漂移曲线，但没人产品化 |
| ⚠️ **但用户要的不是这个** | 用户诉求是「别变」，不是「看它变」 |

**→ 叙事顺序**：「可回滚」是证明手段，「**人格不会漂**」才是入口。
