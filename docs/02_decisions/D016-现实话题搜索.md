# D016 · 现实话题搜索 —— 共享语境终案

- **状态**：已采纳
- **日期**：2026-10-08
- **触发**：HJ 对 D015 手动层的反驳（成立）：「什么都不知道的『刷到了』就是敷衍，
  用户怎么可能聊下去 —— 需要虚拟人物知道用户说的是什么」
- **修正 D015**：共享语境的 L3 搜索层从「远期」提前为本轮实施（可选 key 模式）

---

## 一、需求重定义

原评估把「联网」理解成「她帮你查资料」（助手功能），结论不做。
HJ 的反驳把问题拉回正轨：**用户分享热点时，她必须知道这件事的实质内容**——
细节、来龙去脉、为什么有讨论度——否则「哦我刷到了」撑不起对话，两轮就死。
这不是搜索需求，是**共同认知需求**：真人朋友对世界有共同的信息面。

## 二、方案：关键词预筛 + 触发式搜索（无判断调用）

```
用户消息 → shouldSearch 预筛（本地词表，零成本）
  ├─ 不命中（大多数轮）→ 直接生成，零延迟
  └─ 命中 → Tavily 搜一次（query = 用户消息）→ top3 标题+摘要注入现实区 → 生成
```

- **不做判断调用**（省 1-2s 串行延迟）：词表命中就直接搜；误伤 = 白慢 3s 但
  答案可能更有料（无害）；漏伤 = 世界动态/模型知识兜底（现状）
- **词表原则「宁可漏不可滥」**：覆盖分享/求证/好奇三类
  （「你看」「听说」「热搜」「发布会」「新角色」…），显式排除指令式
  （「帮我查/翻译/写」——那是助手功能，她不接）
- **静默降级**：超时 6s / 无 key / 接口失败 → 空结果 → 区块无痕，
  绝不报错打断聊天
- **注入措辞**：「关于 X，你了解到这些（都是真的，可以大方聊细节和看法）」
  ——她自然地聊，不交代信息来源（AI 身份披露由 R1 常驻徽章承担）

## 三、手动层同步升级

世界动态措辞从「刷到过、没细看就照实说」（怂话倾向，正是 HJ 点名的敷衍）
改为「**你的真实见闻，大方聊，可以补充细节和看法**；条目里没有的细节不要编」。
用户贴的内容多详细，她就知道多详细 —— 贴一段发布会报道她就能聊参数和价格。

## 四、key 与成本

| 项 | 值 |
|---|---|
| 服务 | Tavily（免费层 1000 次/月，个人使用绰绰有余；国内直连可达） |
| key | **可选** —— 不填则整个功能不存在（空配置分发不破坏）；key 只存本机 |
| 触发成本 | 仅命中轮：1 次 Tavily 调用（免费额度）+ 现实区 ~300 token |
| 延迟 | 仅命中轮：+2-3s（聊热点时多等两秒是合理期待） |

## 六、遗留

1. 词表是静态的——随真实使用补词（漏掉的高频话题词往 REALITY_HINTS 加）。
2. Tavily 摘要 240 字/条 ×3 —— 深度话题（如需要长文理解的评测）可能不够聊，
   后续可升 search_depth: advanced（免费层限额内）。
3. 搜索结果的时效窗口由 Tavily 决定（默认含近期内容）；「今天」类话题
   叠加现实区的时间感知可对齐。
