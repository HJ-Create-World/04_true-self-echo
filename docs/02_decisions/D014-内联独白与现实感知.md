# D014 · 内联独白与现实感知

- **状态**：已采纳

- **触发**：HJ 手测反馈 —— ①开了独白但对话里看不到；②问星期/天气她答不明白，

## 一、独白重构：从「独立调用」到「内联输出」

### 原设计的问题（D012 版）
独白只在**主动消息**时出现，且**单独调一次模型**（+512 tokens 成本）。
用户开了开关，日常对话里却永远看不到 —— 功能存在感和成本双输。

### 新设计：她说出口之前的心声
- `DIALOGUE_STYLE` 第六条约定：心里有明显波动时，先用单独一行
  **「〔心想〕……」** 写下真实想法，再正常发消息 —— 多数时候不写
- **解析**：`extractMonologue()`（core/burst.ts）在拆条前剥出独白行
- **落库**：跟随第一条 assistant 消息（`MessageRow.monologue`），回放可见；
  **构建上游历史时只发 content** —— 她的心声不发回去（对方看不见的东西，
  模型也不该看到「自己暴露过」）
- **开关**：设置里的「显示她的内心独白」控制落库+显示；关 = 剥掉丢弃
- **成本：0**（主调用内联，删掉了独立调用）
- 面板的独白按钮（P3-4 的按需生成）不受影响，两者并存

### 🔴 必须剥不必须显的关键
独白行若留在 content 里：落库 → 下一轮进历史 → 模型看到「自己上轮的
内心话」→ 出戏 + 浪费 token。所以解析**无论开关都执行**，开关只管显示。

## 二、现实感知（时间必做 / 天气可选 / 不做通用搜索）

### 评估结论
| 能力 | 结论 | 理由 |
|---|---|---|
| 时间/日期/星期/时段/季节 | ✅ **必做，零成本** | LLM 没有时钟，「今天周五好开心」接不住的根因；几十 token/轮 |
| 天气 | ✅ 可选，open-meteo | **免 API key**（不破坏空配置分发）；城市名可选填；30min 缓存 + 3s 超时 + 失败静默 |
| 通用联网搜索 | ❌ **不做** | 把陪伴者变成助手；延迟/成本/内容审核三重复杂度；用户分享日常接不住的部分靠记忆+对话能力（D013 §七）解决，不靠联网 |

### 实现
- `core/reality.ts`：`renderRealityBlock(now)` 现实区每轮现算
  （不能进缓存的 parts —— 时间是流动的）；`fetchWeatherLine` 带缓存与静默失败
- 段结构插入 `realityBlock`：[头, 正文, 形态区, **现实区**, 记忆区, 尾]
  —— 头尾不变量保持
- 设置页「她的现实感知」：城市名输入（留空 = 只有时间感知）

## 五、已知局限

1. 独白是概率行为（约束「多数时候不要」）—— 连续多轮不出现属正常；
   想稳定观察用面板的手动独白按钮。
2. 天气依赖 open-meteo 可达性（国内直连一般可用）；失败静默 = 只有时间感知。
3. 现实区每轮多 ~40 token。**对前缀缓存无影响**：它插在记忆区之前，
   而 system 的公共前缀 = [头, 正文, 形态区] 逐字节不变 ——
   现实区和记忆区本来就在每轮变化的部分，缓存失效边界没有外移。
