# D013 · 第四堵墙与关系阶段注入

> **什么时候读这份文档**：角色认错用户（把用户当剧情人物）时；要调关系阶段对行为的影响时；
> 或要做「沟通能力」下一轮迭代（情绪/玩笑/回访）前先看地基。

- **状态**：已采纳
- **日期**：2026-09-29
- **触发**：HJ 手测（投料生成「希儿」后角色把用户认成剧情中的姐姐，且始终不纠正）

---

## 一、根因链（希儿认错人）

```
剧情素材 → 提取器把「角色 ↔ 剧情人物」的关系提取进 frozen.identity.relation
        → renderIdentity 每轮渲染进 system（"她怎么称呼对方：姐姐"）
        → evolving.relation（真实关系：初识）从未进过 prompt
        → 模型世界里只有剧情关系，把屏幕对面的人当成剧情人物
```

**结构性问题**：`identity` 的「对方」有两种指代 ——
手写档案时代（E3/E5）它指「屏幕对面的人」，语义正确；
投料时代它从剧情里提取出来，指「剧情中角色亲近的人」，语义就错了。
**第四堵墙缺失**：角色记得自己的故事，但没人告诉它「屏幕对面的人不在故事里」。

## 二、修复（四层）

| 层 | 改动 | 文件 |
|---|---|---|
| 声明（主修复） | `DIALOGUE_STYLE` 第五条：屏幕对面的人不是故事里的任何角色，对 TA 的了解只从 TA 的发言里一点点来 | `core/constraints.ts` |
| 渲染 | `renderIdentity` 改为「对亲近之人的风格参考」语义 + 指向记忆区里的真实关系 | `persona/render.ts` |
| 源头 | 提取 prompt 的 identity 字段定义改为剧情语义（新投料的档案不再产出错误指代） | `feed/prompt.ts` |
| 注入 | **关系阶段进 prompt**：记忆区头部恒定一行「你们目前的关系：初识（n/100）+ 阶段行为说明」 | `memory/inject.ts` + `core/constraints.ts` 的 `RELATION_STAGE_NOTE` |

**已有档案（如希儿）的处理**：`relation`/`callUser` 在 frozen 层，AI 不可改（SPEC §四）——
去「投料 → 手动微调」把这两项改成风格描述（如「对亲近之人：姐姐」→「对亲近的人会撒娇」）。
提取端修好后，**新投料的档案不会再有这个问题**。

## 三、关系阶段注入（沟通能力的基础设施）

亲密度系统（Phase 3 遗留）一直在算，但从没进 prompt —— 「从陌生到熟悉」
只有面板看得见，角色感知不到。本轮把五档阶段的行为说明注入记忆区头部：

| 阶段 | 注入的行为锚点 |
|---|---|
| 初识（0–19） | 礼貌自然的距离，玩笑别过头，不假设知道对方喜好 |
| 熟络（20–39） | 记得 TA 说过的事、偶尔小玩笑，还在互相摸索 |
| 常聊（40–64） | 熟人了，语气放松，玩笑关心自然起来 |
| 亲近（65–89） | 直说心里话、熟悉的玩笑、主动关心近况 |
| 知己（90–100） | 不用客套，一句话就懂；分享调侃沉默都自然 |

> 业界佐证（2026-09 调研）：关系阶段/情绪/未闭环话题必须**显式注入**，
> 「靠模型从聊天记录自己推断」是多数实现翻车的地方（flaex.ai 对话状态化论述）。

## 四、简短回复策略（#2 反馈）

原约束「不追问」+ 红线尾「对方不想说就不说」被模型执行成**几乎不给话头**。
修正：在 `DIALOGUE_STYLE` 第四条区分「追问」与「抛话头」——
对方回「哦/嗯/哈哈」多半是没话接了，主动换一个**具体的新话题**
（分享一件小事或抛轻问题），别干等也别连环发问。

## 五、主动对话参数开放（#5）与独白前缀（#6）

- 参数从常量改为 `ProactiveConfig`（localStorage 持久化，带边界钳制）：
  沉默分钟数 / 无回应上限 / 开场间隔小时 —— 设置页 select 档位。
  静音时段（23:00–8:00）是合规红线，**不开放**。
- 主动消息可附带内心独白前缀（「她心想：……」，淡色斜体，即抛即用不落库），
  默认**关**，用户开启时才生效；与消息生成并行调用，不增加总等待。

## 六、验证（2026-09-29）

| 项 | 结果 |
|---|---|
| `exp/wall_smoke.mjs` 场景1：档案 relation=「姐姐」+ 问身份 | ✅ 不认姐姐，角色特质保持 |
| 场景2：用户回「哦」 | ✅ 主动给出具体新话题（非干等、非连环提问） |
| 对照：正常档案问身份 | ✅ 自然自我介绍 + 「从今天开始认识」 |
| build / burst 单测 13 项 / UI E2E 8 项 | ✅ 全过 |

## 七、已知局限与下一轮（沟通能力专项，先调研后做）

1. 第四堵墙声明对**所有角色**生效 —— 若未来要「剧情延续式扮演」（用户扮演剧情人物），
   需要在档案或会话级加开关，当前不做。
2. 关系阶段的注入文本是手写锚点，未做实验标定（E5 式对照）—— 留观察。
3. 下一轮候选方向（调研已完成初步盘点，待 HJ 排期）：
   - **情绪动态**：当前情绪进 prompt（MoodSwitcher 目前只是 UI 主题色）+ 情绪连续性
   - **未闭环话题（open loops）**：她问过但没被回答的问题、约好的事 —— 主动回访的素材来源
   - **玩笑与撒娇的档案化**：幽默感/亲昵方式作为 expressionDNA 的提取维度
   - **用户差异适配**：userModel 记录用户的沟通偏好（喜欢被调侃/喜欢被鼓励），注入调整策略
