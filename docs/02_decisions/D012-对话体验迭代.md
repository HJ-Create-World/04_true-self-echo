- **状态**：已采纳

- **决策者**：HJ（三项拍板：全做 L0+L1+L2 / 默认开+保守参数 / 逐条延迟显示）
- **触发**：用户反馈两条 —— ①回复偏「答题」，不主动开口就把天聊死（内向用户完全停滞）；②一人一句太机械，真人是连发短消息

---

## 结论先行

| # | 决策 |
|---|---|
| 1 | **连发 = 单次调用 + 空行分隔 + 前端拆条**（多次调用成本 ×N，JSON 输出解析更脆，都不如它） |
| 2 | **用户连发不丢弃**：生成期间输入进队列，turn 结束后合并为下一轮 |
| 3 | **主动对话做三级**：L0 prompt 对话策略 + L1 开场白（>6h）+ L2 沉默触发（10min） |
| 4 | **L2 保守默认**：连续 2 次无回应即停；23:00–8:00 恒静音（不受开关影响）；设置页可关 |
| 5 | **显示节奏**：逐条延迟（600ms + 40ms/字，封顶 3.2s），第一条即时 |
| 6 | **主动消息的指令不落库** —— 历史里只有她的自然发言 |
| 7 | 对话形态约束独立成 `styleBlock` 段，**不写进人格档案**（投料提取器会抄走） |

---

## 背景：两条用户反馈的根因

1. **「把天聊死」**——RLHF 默认模式：有问必答、答完即止。不是人格问题，是所有对话
   模型的通性；E5（D007）打的就是这个，但当时只压了「不越界」，没给「怎么延续」。
2. **「一人一句」**——上一版把一次生成当一条消息落库，形态上就是「作文」而不是「发消息」。

## 调研结论（2026-09-29）

| 参照 | 做法 | 采纳 |
|---|---|---|
| SillyTavern MessageQueue | 分隔符拆条逐发 | ✅ 思路（分隔符改用空行——IM 分段习惯，遵循度更高） |
| LoversLab 社区踩坑 | 模型常「多条堆一条」 | ✅ prompt 明示 IM 语境 + 解析容错（无空行=单条） |
| Nomi（业界最佳） | 节奏可配 / 内容来自对话历史 / 静音时段 | ✅ 静音时段 + 内容策略 |
| Replika | 主动消息可配置可关闭 | ✅ 设置页开关 |
| Character.AI | 纯被动 | ❌ |

**本项目无推送能力（纯本地）**，主动范围限定页面打开时 —— 与 Nomi「在场才主动」一致，
也天然规避了后台推送的骚扰面。

## 关键设计（为什么这样做）

1. **落库粒度 = 拆条后逐条**：历史回放时 assistant 就是多条短消息，
   下一轮模型看到的是真实 IM 形态，不需要任何特殊标记。
2. **隐藏指令不落库**：落了库，下一轮模型看到「系统让我主动」就出戏；
   不落库，她的主动发言与真实记忆无缝。指令用全角括号场景指令
   （`monologue.ts` 同款惯例）。
3. **主动消息不做记忆抽取**：没有用户输入，演化层不变 → 无快照，天然跳过。
4. **主动失败完全静默**：用户没有请求这次生成，报错反而是打扰；`console.warn` 留痕。
5. **E5 不变量未破坏**：约束头最顶 / 约束尾最末两条不变量保持；`styleBlock`
   插中间与记忆区同级（先例：Phase 3 记忆区）。
6. **独白剥掉 styleBlock**：独白不是「发消息」，连发约束会误导输出。

## 已知局限（随结论带上）

1. **六维分数不再与之前严格可比** —— system 加了形态区，输入形状变了
   （同 Phase 2 收尾的口径：形状变化要声明，不要悄悄混进历史分数）。
2. **连发是概率行为不是保证**：temperature 0.8 下多数轮连发，偶尔单条 ——
   单条本身是合法形态（「多数时候只发一条」就是约束原文）。
3. **L1/L2 的长时触发（>6h / 10min 沉默）未自动化验证** —— 需手测
   （`MANUAL_TEST.md` §14），或在需要时给 store 加测试钩子。
4. **多轮对话下连发密度的长期稳定性未观察** —— 留真实使用数据。
