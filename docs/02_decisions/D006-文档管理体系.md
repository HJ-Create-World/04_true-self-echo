# D006 · 文档管理体系

> **什么时候读这份文档**：当你想推翻文档分层、想新建目录、想不通"为什么要求这么严"时。
>
> **它不是**：具体操作规范（那是 `00_meta/DOC_STANDARD.md`）。
>
> **它能回答**：为什么用编号目录？为什么强调单一信息源？为什么废弃文档要物理隔离？

---

## 状态

✅ 已定

## 背景

项目立项 1 天，文档从 0 涨到 28 份。**已实际发生的冲突**：

| 冲突 | 具体 |
|---|---|
| **链接全断** | `PROJECT.md` 链接写 `D002-人格双层架构.md`，实际文件名是 `D002-核心抽象-人格档案.md` |
| **文件名错** | 正文写 `D003-技术架构.md`，实际是 `D003-架构选型.md` |
| **状态矛盾** | `PROJECT.md` 顶部写"Phase 0 待执行"，第二节写"已完成" |
| **同事实两处** | 人格剖面在 `PROJECT.md` 和 `SPEC.md` 都写了，SPEC 改了 PROJECT 没改 |
| **职责混杂** | `PHASE0_人格提取验证.md` 同时是"执行记录 + 执行脚本 + 操作说明"，顶部写"已完成"、底部写"待执行"、中间写"现在就开始" |
| **过期内容** | 该文件里贴的 v1 Prompt 草案已被 `phase0/Prompt-提取.md` 的正式版取代，但没删 |

**关键**：一个只有 28 份文档、成立 1 天的项目，已经出现 6 类冲突。**不做治理，到 100 份时无法维护。**

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| **A 维持现状** | 零成本 | 冲突持续累积，LLM 会读到矛盾版本 |
| **B 只加规范不重构** | 成本低 | 历史遗留冲突仍在，规范会和现状打架 |
| **C 分层目录 + 单一信息源 + 状态机 + 物理归档** | 根治；对 LLM 友好 | 一次性重构成本（约 25 个文件迁移） |

## 决策

**选 C。**

### 具体设计

**1. 八目录分层（按"回答什么问题"分，不按格式分）**
```
00_meta/  找东西    01_product/  做什么   02_decisions/ 为什么
03_specs/ 怎么做    04_lab/      测到什么 05_research/  别人怎么做
06_ops/   怎么操作  _archive/    已废弃
```

**2. 单一信息源（SSOT）** —— 每个事实只在一个文件里定义，别处只引用不复制。

**3. 状态机** —— 每份文档带 `status` frontmatter，且必须在 `AGENTS.md` 里显式告诉 agent 去读它（否则对 LLM 隐形）。

**4. 物理归档** —— 废弃文档**移入 `_archive/`**，不只打横幅。

## 理由

### 为什么必须治"同一信息多处存在"

对 LLM 的伤害有四步机制：

1. **检索**：LLM 没有"时效"和"权威"概念，过期版和现行版同等对待
2. **排序**：同一事实的多版本语义相似度极高，这正是 rerank 最难区分的形态
3. **冲突**：模型会**合成一个不存在的中间版本** —— 最危险，因为它读起来完全合理
4. **固化**：错误结果写进新文档 → 下轮命中三个版本 → 加速恶化

**另有独立证据**：2025 年 Chroma 对 18 个模型的实测显示，**上下文长度本身就会降低输出可靠性**，连"复制重复词"这种平凡任务都退化。所以"全量喂文档"的代价不只是找不到，而是在别处悄悄变笨。

### 为什么用数字前缀

让目录按"信息层级"而非字母序排列，且一眼看出建议的加载顺序。

### 为什么废弃文档要物理隔离

**只打「已废弃」横幅是不够的**：
- 横幅**未必在检索片段里**（LLM 可能只看到中间一段）
- 废弃文档与有效文档的**语义相似度一样高**，检索器无法区分

## 代价

| 代价 | 说明 |
|---|---|
| 一次性重构成本 | 25 个文件迁移（已用 `git mv` 完成，保留历史） |
| 写文档多一步 | 填 frontmatter + 写导语块 + 登记 INDEX |
| **需要纪律** | 规则不执行等于没有。**每次新增文档都要问"这信息是不是已经有了"** |

## 什么情况下要重审

- 目录数超过 10 个 → 说明分类出了问题
- 出现"某份文档不知道该放哪" → 说明该拆文档或该补规则
- `INDEX.md` 需要人工反复修正 → 说明登记机制太重，需要自动化
