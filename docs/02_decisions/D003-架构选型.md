# D003 · 架构选型：方案 B（前端 + 本地薄后端）

- **状态**：已采纳
- **日期**：2026-09-16
- **决策者**：HJ

---

## 背景

HJ 的要求组合起来有点矛盾：

1. 想调用**云端大模型 API**（本地性能有限）
2. 想**保护隐私**，不想让别人看到私人对话
3. **预留 API Key 的设计**
4. 本地电脑跑不了好模型，要能切到云端
5. 先做网页，跑通后再扩展桌面端和 App
6. 允许引入 UI 库

「纯前端静态站」听起来最省事，但和 1、3 直接冲突。

---

## 选项

| 选项 | 描述 | 致命问题 |
|---|---|---|
| A · 纯前端静态站 | 全在浏览器跑，`npm run build` 出来就是成品 | ❌ 浏览器**不能**直接调用 Ollama（跨域 + 无 HTTP 权限）<br>❌ API Key 必须写进前端代码，等于公开<br>❌ 无法读写本地文件 |
| **B · 前端 + 本地薄后端** | 前端照常写；额外一个极薄的本地服务，只做三件事 | 需要多跑一个进程 |
| C · 完整前后端架构 | 正经后端服务 + 数据库 + 用户系统 | ❌ 对本项目是过度设计，直接触发烂尾模式 |

---

## 决定

**采纳 B。** 后端的定位必须说清楚：

> **不是一个系统，是一个传话人。**

它只有三个职责：

| # | 职责 | 说明 |
|---|---|---|
| 1 | 代理 LLM 请求 | 转发给云端 API 或本地 Ollama；Key 存在这里，不暴露给浏览器 |
| 2 | 读文件 | 用户可以投料本地文档 |
| 3 | 写文件 | 导出人格档案 / 对话记录 |

**硬约束**：
- 一个文件，**≤ 200 行**
- 不引入数据库、不做用户系统、不做鉴权
- 删掉它，项目能**降级为方案 A**（牺牲本地模型和 Key 保护，其余照常跑）

---

## 技术选型

| 层 | 选择 | 为什么 | 明确不用 |
|---|---|---|---|
| 前端框架 | **Vue 3 + TypeScript + Vite** | HJ 系统学过 Vue，这是唯一不需要学的部分 | React（要重新学） |
| 状态管理 | **Pinia** | Vue 官方推荐，轻量 | Vuex（Vue2 时代产物） |
| 路由 | **Vue Router** | 标准配置 | — |
| UI 库 | **允许引入**（具体待定） | HJ 明确允许；风格未定，**需要预留可调整空间** | 深度定制化的重型 UI 库 |
| 样式 | **CSS 变量驱动的主题层** | 风格未定 → 先用变量把颜色/圆角/间距抽出来，换主题只改一处 | 硬编码颜色 |
| 后端 | **Node.js + 单文件 HTTP 服务** | 与前端同语言，不引入新知识 | Express/Koa 全家桶 |
| 本地存储 | **IndexedDB** | 浏览器原生，能存大量对话；无需后端 | localStorage（容量太小） |
| 模型接入 | **OpenAI 兼容接口 + Ollama** | 一套代码适配两家，切换只改配置 | 各家 SDK |
| 语音（Phase 5） | 后置，候选 GPT-SoVITS / IndexTTS-2 / CosyVoice 2 | 见 SPEC / PLAN | 现在就定 |

---

## 后果

**正面**
- API Key 安全（存在后端，不进浏览器）
- 本地模型可用（后端能调 Ollama）
- 桌面端/App 扩展路径顺畅：Electron/Tauri 把前端 + 薄后端打包即可，不用重写
- **可降级**：后端删掉项目还能跑，不会因为这块卡死

**负面 / 代价**
- 启动时可能需要跑两个进程（开发阶段用 Vite 代理可合并）
- 多了一个「用户得理解」的东西 —— 违反「薄」的直觉。但它的表面积足够小，看懂成本可控

**后续维护点**
- 后端一旦超过 200 行，说明有人在往里塞职责 → 停，重新评估
