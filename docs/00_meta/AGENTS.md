>
> 这份文件解决一个问题：**在有限的上下文里，如何在正确的时间读到正确的那一份文档。**

## 三、必须遵守的规则（违反会造成项目损坏）

### 规则 1：先查 INDEX，再读文件
`docs/00_meta/INDEX.md` 是所有文档的登记表。**不确定某信息在哪时，先读它**，不要靠猜文件名。

### 规则 2：单一信息源（Single Source of Truth）
每个事实**只在一个文件里定义**，其他文件只能**引用**它，不能复制内容。

| 事实 | 唯一归属 | 别处怎么写 |
|---|---|---|
| 产品定位 / 范围 | `01_product/SPEC.md` | 只写「见 SPEC §1」，不复制 |
| 当前进度 / 状态 | `00_meta/STATUS.md` | 只写「见 STATUS」，不复制 |
| 决策结论 | `02_decisions/Dxxx-*.md` | 只写「见 D003」，不复制理由 |
| 数据结构字段 | `03_specs/persona-schema.md` | 只写「字段见 schema」，不复制字段表 |

> ⚠️ **这是本项目最容易犯的错。** 以前已发生过：`PROJECT.md` 和 `SPEC.md` 都写了人格剖面，改了 SPEC 忘了改 PROJECT，导致两份不一致。
> **如果你要写的信息已经在别处存在，不要复制 —— 去改那一处，或者在原处补充。**

### 规则 3：改完文档要查引用
如果你**改了文件名**或**移动了文件**，必须检查有没有其他文件引用了它。用 Grep 搜旧文件名。

### 规则 4：状态字段必须准确
每份文档头部都有 `status` 字段：

| status | 含义 | 你能用它做什么 |
|---|---|---|
| `active` | 当前有效 | ✅ 可以当依据 |
| `draft` | 草稿，未确认 | ⚠️ 可参考，不可当依据 |
| `superseded` | 已被取代 | ❌ 不要用，去看它指向的新文件 |
| `archived` | 已归档 | ❌ 不要用 |

> ⚠️ **`_archive/` 目录里的东西一律不要作为依据。** 即使内容看起来对，也可能已经过期。
> 如果你发现自己在引用 `_archive/` 的内容，停下来，去找当前的对应文档。

### 规则 5：实验数据不可改，只可追加
`04_lab/` 下的原始测试数据（`E1-*.md` / `E2-*.md` 等）是**历史事实**。
它们记录的是"当时测到了什么"，**不是"正确的结论"**。即使后来发现结论有错，也不要改原始数据 ——
**另建一份新实验，或在 `04_lab/README.md` 里注明"E1 的结论已被 E5 修正"。**

## 四、Frontmatter 约定

每份文档都以 YAML frontmatter 开头。**你必须读它**，因为它告诉你这份文档能不能用：

```yaml
---
title: 文档标题
type: adr | spec | lab-report | research | guide | index | status
status: active | draft | superseded | archived
updated: YYYY-MM-DD
owner: HJ
related: [其他文档的编号或文件名]
---
```

> ⚠️ **Frontmatter 对 LLM 不是自动可见的** —— 你必须主动去读它。
> 特别要检查 `status`：如果是 `superseded` 或 `archived`，**不要使用该文档的内容**。

## 五、写作要求（你写新文档时）

1. **每份文档开头必须有「什么时候读这份文档」导语** —— 一句话说明它的用途和边界
2. **结论先行** —— 第一段就给出结论，细节在后
3. **禁止无法验证的形容词** —— "有韵律感""很优雅"这类词不许出现；要写"句子平均 12 字"这种可验证的
4. **不确定就写"未获取"/"证据不足"** —— 绝对不要编造数据、链接、星数、日期
5. **引用外部资料要标来源** —— 文件路径 + 行号，或 URL

## 六、项目一句话

**persona-forge（人格工坊）**：喂给它一个人说过的话，它就能像那个人一样和你聊天，而且你能看见它记住了什么、变成了什么样。

- 技术栈：Vue3 + TS + Vite + Pinia + IndexedDB + Node 薄后端
- 当前阶段：见 `docs/00_meta/STATUS.md`
- **不做**：模型微调、实时语音、多用户、公开分享社区
