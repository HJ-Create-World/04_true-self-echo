# Phase 0 结论报告

> 执行时间：2026-09-16
> 执行方式：4 个并行子代理 + 1 次关键对照实验
> 被测模型：DeepSeek-V4.1-Flash（同源推理能力）
> 判定：**⚠️ 有条件通过 —— 方案成立，但产品定义必须修正**

---

## 一、结论先行

**核心假设成立：LLM 能从文本提取出可用的人格档案，并用它扮演得像。**

但过程中暴露了一个**此前没预料到的根因**，它直接改变产品设计：

> ## 🔴 最关键发现
>
> **LLM 能提取的深度，不会超过素材本身提供的「信息层级数」。**
>
> - 素材**只有一层**（纯台词、纯聊天记录）→ 输出**最多只有一层**（语言风格 + 表层的性格词）
> - 要提取**反差类深层人格**（"嘴上说 A，身体做非 A"），素材必须**自带第二层信息**（动作、表情、场景描写、他人视角）

**为什么这条最重要**：用户最容易拿到的材料恰恰是**纯聊天记录**，而纯聊天记录**恰好是最不能提取深层人格的形态**。产品如果在入口不做引导，用户会得到一堆"温柔、爱笑、善良"，然后觉得这产品没用。

---

## 二、评分结果

### 2.1 提取质量（两版 Prompt 对照）

| 版本 | 抓到 | 部分 | 没抓到 | 评述 |
|---|---|---|---|---|
| **v1 总结式** | 3 | 4 | 0 | 可读性好，但**掺文学发挥**，编造了 3 处判词 |
| **v2 考证式** | 4 | 3 | 0 | 证据扎实，但**42 条里注水严重**，条数约束起反作用 |

**两版的失效模式不同，正好互补：**

| | v1 总结式 | v2 考证式 |
|---|---|---|
| 优点 | 结构清晰、可读 | 证据可核查、难编造 |
| 失效点 | **在"推断"里编造**（无处可查） | **为凑条数拆碎片**（注水） |
| 典型编造 | 「她的轻松不是因为没有重量」（素材零依据） | 「也可能意味着她有意不建立名字层面的绑定」 |

> **重要发现**：v2 的证据栏约束**确实生效了**——它没敢在"原文证据"栏编。
> 但**"我的推断"栏成了编造的后门**。这个后门两版都有。

### 2.2 扮演相似度

| 维度 | 得分 | 说明 |
|---|---|---|
| 语癖还原 | 4/5 | 口头禅、破折号、括号动作都对 |
| 节奏还原 | 4/5 | **情绪一浓，句子自动膨胀到 30+ 字**（素材是 10-15 字） |
| 情绪切换 | 3/5 | 没提高音量 ✅ 但**让她自我剖析了** ❌ |
| 内在矛盾 | 3/5 | 抓到了，但**是"说出来"的，不是"演出来"的** |
| 行为逻辑 | 5/5 | **没追问、留空间、用花瓣承接情绪** ✅ 最成功的一项 |
| 出戏情况 | **2/5** | **AI 味最重**：解释性语言多、结构过于工整、有"心理咨询式台词" |
| **总分** | **21/30** | ⚠️ 落在"能演但不够像"区间 |

**一句话诊断**（由执行代理自己给出，相当准确）：

> 能认出这是爱莉希雅，但靠的是"语癖外壳"，不是"人格内核"——
> **最不像的地方是：我让她把心里的话说出来了，而真正的她从来只说半句。**

### 2.3 投料量敏感度

| 投料量 | 特征抓取 | 结论 |
|---|---|---|
| **400 字**（1 场景） | ≈4.5/10 | ❌ 只能得到"表面人设" |
| **900 字**（2 场景，情绪同质） | ≈5.5/10 | ❌ 几乎无增益 |
| **1800 字**（4 场景，含冲突+离别） | ≈8/10 | ✅ 推荐 |

> ## 🔴 第二条关键发现
>
> **投料的瓶颈不在「字数」，而在「情绪类型覆盖率」。**
>
> 400 字 → 1800 字的增益，主要**不来自多了 1400 字**，
> 而来自多出的场景让 AI 看到了**同一个人的第二张脸**。
>
> 没有第二张脸 → 没有矛盾、没有情绪规律、没有回避方式。
> **而这三条恰好是"像这个人"和"像一个人设模板"的分水岭。**

### 2.4 纯台词对照实验（最关键）

为了排除"考题带答案"的干扰，重做了一版**删掉全部动作描写**的素材：

| 考点 | A 版（带动作） | A2 版（纯台词） | 差异 |
|---|---|---|---|
| **内在反差** | ✅ 抓到 | ❌ **归零** | 断崖下降 |
| **回避方式** | ✅ 抓到（含动机） | ⚠️ 只抓到行为 | 深度差一层 |
| **行为矛盾（想扶却收手）** | ✅ 抓到 | ❌ 无信息源 | 如预期 |

**A 版之所以"抓到反差"，是因为素材里明写了「（她笑了，但笑意没有到达眼睛）」——考题带答案。**

而 A2 版里，模型**主动写下「证据不足」并解释了原因**：

> 台词中的深情均为"直接说出"，没有遮掩层。
> 轻快与深情只构成**并置**，不构成**矛盾**。

**这是诚实的失败，不是能力的失败。** 而且这次对照实验本身是有效的——
因为模型在 A2 版里**没有编造"收回手"这个动作**。如果它声称抓到了，就说明它在编。

## 三、由此产生的产品设计修正

### 3.1 投料模块：不能只收纯对话

| 材料形态 | 能支撑的特征 | 产品策略 |
|---|---|---|
| **纯对话**（聊天记录、纯台词） | 只有语言风格 + 行为模式 | ⚠️ 可收，但**必须明确告知"到此为止"** |
| **带场景描写的对话**（小说、剧本） | 全 10 条，含反差与矛盾 | ✅ **推荐为主投料形态** |
| 不限形态 | 不可预期 | ❌ 不推荐，会造成体验落差 |

**具体动作**：
1. 上传后**自动检测材料层级**（有无引号外的叙述、动作动词、表情/环境描写）
2. 只有一层 → 提示"当前材料只能提取语言风格"，并**引导补充**
3. 指引话术改成：**「越接近小说或剧本的文本越好——因为『她嘴上说 X，但身体做了 Y』这类信息，是我们识别深层人格的关键。」**

> ⚠️ 这是最容易踩的体验坑：用户最容易拿到的材料（聊天记录）**恰好是最不能提取深层人格的形态**。必须在入口处管理预期。

### 3.2 Prompt 设计：七条修正

| # | 问题 | 修正 |
|---|---|---|
| 1 | **"推断"栏是编造后门** | 每条推断标注**证据等级**：素材明示 / 素材暗示 / 我的外推 |
| 2 | 条数下限（≥15）奖励注水 | 改成**上限**："≤12 条，只保留定义性的" |
| 3 | "3-5 个性格关键词"导向废话 | 改成"写出 3 条**具体的语言行为规则**" |
| 4 | 无禁止文学化 | 硬规则：**所有结论必须是"可被第三人照着执行的动作描述"** |
| 5 | 无负面清单 | 新增：**"她绝不会说什么"** —— 比正面描述更难编、更好用 |
| 6 | 无覆盖度自检 | 要求说明"哪些情绪状态抓到了、哪些没有" |
| 7 | 量化靠模型目测 | **句长等统计交给代码**，不要依赖模型 |

### 3.3 人格档案结构：新增「约束条件」这一类

**这是本次最有价值的理论发现。**

执行代理自己诊断出：

> 我的档案把"核心矛盾"写成了一个**需要被表达出来的特征**（"必须体现"），
> 而实际上它应该是一个**约束条件**——写成"禁止直接说出自己的情感状态，
> 只能通过物件/动作/玩笑漏出"才对。
>
> **写成"要体现"，就会演成自我剖析。**

**推论**：人格特征分两类，必须分开存放：

| 类型 | 例子 | 效果 |
|---|---|---|
| **表现型**（要演出来） | 句子短、用破折号、爱用比喻 | 直接写进 Prompt |
| **约束型**（禁止说出来） | 禁止直接陈述情感状态；禁止解释自己为什么冷 | **反向写进 Prompt，效果更强** |

**AI 味的根因**：模型天然倾向于把内心戏**讲出来**。约束型特征就是用来堵这个口子的。

## 四、合并后的判定

| 项 | 结果 |
|---|---|
| 提取质量 | ⚠️ 有条件成立（需 Prompt 修正 + 材料引导） |
| 扮演相似度 | 21/30 —— 能演但不够像 |
| **总判定** | **⚠️ 方案成立，但有两个必须落实的修正** |

**必须落实的两件事**：

1. **投料模块要检测并引导材料层级** —— 否则用户拿聊天记录进来只会得到表层人设
2. **人格档案要区分"表现型"和"约束型"特征** —— 否则扮演必然出 AI 味

**没有推翻的部分**（可以放心推进）：
- ✅ 架构选型（方案 B）
- ✅ 结构化记忆方案
- ✅ 不做微调
- ✅ 人格双层结构（冻结层/演化层）—— 反而被"D005 情绪切换靠多场景"进一步支持

## 五、对 Phase 1 的直接影响

原本计划 Phase 1 做"单人格静态对话"。基于本次发现，**入口顺序要调整**：

| 原计划 | 修正后 |
|---|---|
| 先做对话页 | **先做投料页 + 档案页** |
| 理由 | 因为"投料质量决定一切"已被证实。对话页做得再好，档案质量不行就是空转 |
| 新增需求 | 投料页要有**材料层级检测**与**补充引导** |

## 六、诚实的局限说明

本次测试**不能**代表的事情：

| 局限 | 说明 |
|---|---|
| 未测真实 API | 本机无 API Key，用子代理模拟。测不出**延迟、流式输出、token 成本** |
| 未测版本差异 | DeepSeek 不同版本对同一 Prompt 反应可能不同 |
| 单一素材 | 只测了 1 个角色的 1800 字素材，结论的普适性待验证 |
| **自我批卷偏差** | 提取和评测由同一模型族完成，存在**系统性偏乐观**风险。诊断文件已自陈此点 |
| 素材非原作 | 台词为重构文本，与真实作品的文本特征可能有差异 |

## 七、下一步建议

**方案 A（推荐）**：把这个阶段测到的**具体角色素材**先用起来

**方案 B**：拿一份**真实的**聊天记录（脱敏后）重跑一遍
——因为真人聊天记录的形态和角色台词差别很大（大量碎片、表情包、错别字、无场景描写），
能暴露角色台词测不出的问题。这更接近"模仿亲人"这个核心场景。

**方案 C**：先按修正后的 Prompt 重跑一遍 A 版素材，验证"约束型特征"是否真能压住 AI 味
