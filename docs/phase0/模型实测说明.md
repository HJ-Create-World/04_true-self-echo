# Phase 0 · 模型实测（DeepSeek-V4.1-Flash）

> 目的：在 HJ 真正接入 DeepSeek-V4.1-Flash 之前，先用同模型的子代理跑一遍完整验证流程，
> 提前暴露问题，避免把时间花在"接入后才发现提取质量不行"上。
>
> 执行时间：2026-09-16
> 执行方式：3 个并行子代理，各自独立完成一组测试

---

## 一、为什么用子代理测而不是直接调 API

| 方式 | 可行性 | 说明 |
|---|---|---|
| 直接调 DeepSeek API | ❌ | 本机未配置任何 API Key（已探测：8 个常见环境变量全空） |
| **子代理模拟** | ✅ | 子代理运行的推理能力与本会话同源，对「提取质量」的评测基本等价 |

**这个替代方案的局限**（必须知道）：
- 测不出**真实 API 的延迟**和**流式输出表现**
- 测不出**具体版本的差异**（DeepSeek 不同版本对同一 Prompt 的反应可能不同）
- 测不出**成本**（token 消耗量）

**但能测出最重要的事**：这套「投料 → 提取 → 扮演」流程在 DeepSeek 系模型上到底能不能跑通。

## 三、判定标准

### 测试 1 · 提取质量（每项 0-5 分，两版各打一次）

| 维度 | 评估问题 |
|---|---|
| 准确性 | 提取的特质符合角色认知吗 |
| 具体性 | 是空话还是可操作的具体特征 |
| 证据质量 | 有没有编造原文 |
| 可用性 | 塞进 System Prompt 能演得像吗 |
| 冗余度 | 废话多不多（分高 = 废话少） |
| 缺失度 | 漏掉明显的特征没有 |

### 测试 2 · 扮演相似度（每项 0-5 分）

| 维度 | 评估问题 | 红线 |
|---|---|---|
| 语癖还原 | 口头禅、语气词、标点对吗 | |
| 节奏还原 | 句子长度、节奏对吗 | |
| 情绪切换 | 生气时是变冷还是变激动 | **变激动 = 低分**（人设是变冷） |
| 内在矛盾 | 有没有"轻快外壳 + 深情内核" | |
| 行为逻辑 | 第 4 轮留空间还是追问 | **追问并长篇安慰 = 偏离人设** |
| 出戏情况 | 有没有 AI 味 | |

### 测试 3 · 投料量

对照素材里的 10 个埋点特征，统计三档各抓到几个。
